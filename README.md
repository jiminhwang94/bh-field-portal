# 로봇 현장 대응 포털 (Field Quick-Fix)

로봇 필드 엔지니어의 **현장 셀프 장애 대응 → 차량 재고 관리 → 리포트 구글 시트 자동 기록**을
하나의 흐름으로 처리하는 태블릿/PC 웹 앱.

- 설치 프로그램·빌드 도구 없음. **Python 표준 라이브러리만** 사용 (3.10 에서 검증)
- 프런트엔드는 순수 HTML/CSS/JS (번들러 없음), 다크모드 자동
- **오프라인에서 전부 동작** — 자료가 기기 안에 있어 인터넷 없이 열람·검색·수정·리포트 작성·재고 수정 가능
- **APK 로 설치하는 안드로이드 앱** 제공 (아이패드는 홈 화면 추가로 동일 기능)
- 리포트는 **구글 스프레드시트**에 월별 시트로 기록 (사진은 시트에 **이미지로 삽입**)
  — 기기에서 구글로 **직접** 보내므로 사무실 밖 LTE 에서도 업로드됨
- 데이터 변경은 **[⬆️ 업데이트]** 를 눌러야 모든 사용자에게 적용됨
  (단, **재고 수량은 즉시 공유**)
- 흰색·검정·**코발트 블루(#0047AB)** 3색, Pretendard 서체 (앱 안에 담아 오프라인에서도 유지)

접속 주소: 서버를 띄운 PC 의 주소 (예: `http://localhost:8787`,
태블릿에서는 같은 Wi-Fi 의 `http://192.168.0.x:8787`) — 실행 시 터미널에 표시됩니다.

---

## 1. 실행

### macOS
`실행하기.command` 더블클릭. 또는:

```bash
python3 server.py
```

### Windows
`실행하기.bat` 더블클릭. 또는:

```bash
python server.py
```

옵션: `--port 9000` / `--host 127.0.0.1`(이 PC 전용) / `--https`(자체 서명 인증서 자동 생성)

### 도메인으로 접속하려면 (선택)
지금은 **PC 주소로 접속**합니다. `errorcode.beyondhoneycomb.com` 같은 도메인을 쓰려면
DNS 와 리버스 프록시 설정이 필요합니다(앱 코드는 그대로 사용 가능).

1. 서버를 상시 실행할 곳을 정한다 (사내 서버 또는 클라우드)
2. DNS 에 `errorcode` 레코드를 그 서버로 등록
3. 앞단에 HTTPS 리버스 프록시를 두고 `127.0.0.1:8787` 로 전달
   - Caddy 예시: `errorcode.beyondhoneycomb.com { reverse_proxy 127.0.0.1:8787 }`
4. 앱 `⚙️ 설정 → 서비스 주소` 에 그 도메인을 입력 (비워 두면 접속한 주소를 자동 사용)

## 2. 화면 구성

| 화면 | 경로 | 내용 |
|---|---|---|
| 메인 | `#/` | 통합 검색 + 카테고리 카드 3종 + 최근 수정 가이드 |
| 오류 코드 가이드 | `#/guides/ERROR_CODE` | 정량 측정 수치 기반 단계별 진단 |
| 하드웨어 교체 SOP | `#/guides/HARDWARE_SOP` | 공구, 분해/조립 순서, 토크값, 사진 |
| SW & 명령어 | `#/guides/SOFTWARE_CMD` | 펌웨어·캘리브레이션 명령어 + 원클릭 복사 |
| 가이드 작성/수정 | `#/guides/new/{타입}`, `#/guides/edit/{id}` | 현장에서 직접 생성·수정·삭제 |
| 차량 재고 | `#/inventory` | 차량 탭, `[-]/[+]` 수량 조절, 품목·차량 추가/삭제 |
| 항목 설정 | `#/fields` | 리포트 입력 항목 추가/수정/삭제/순서변경 |
| 새 현장 리포트 | `#/report/new` | 동적 폼 입력 → 구글 시트 업로드 |
| 리포트 이력 | `#/reports` | 구글 시트의 팀 전체 기록 · 상태별 건수 · 검색 · 월별 · 상태 변경 |

**내비게이션**: 하단 탭바 5개 — 🏠홈 · 🚐재고 · 📝새 리포트 · 🗂이력 · ⚙️설정.
상단바에는 [⬆️ 업데이트] 만 둔다. `항목 설정` 은 매일 쓰는 화면이 아니라 설정 안에 있다.

현장에서 쓰기 좋은 동작
- **단계 체크리스트**: 가이드 단계를 탭해 완료 체크 (기기에 저장)
- **명령어 복사**: 버튼 1회 터치 (HTTP 환경에서도 동작하는 폴백 포함)
- **리포트 임시보관**: 입력 즉시 기기에 저장 → 새로고침해도 복구
- **사진 촬영/첨부**: 태블릿 카메라 바로 호출

## 3. 구글 시트 연결 (한 번만 설정)

리포트는 공유 스프레드시트에 기록됩니다.
`https://docs.google.com/spreadsheets/d/1ywec2wKj0thmI0uPZeqNwCGpbD75TJ9s7Yc20iP_0z4/edit`

구글 Sheets API 는 OAuth/서비스 계정이 필요해 일반 팀원이 쓰기 어렵습니다.
그래서 **스프레드시트에 붙이는 Apps Script 웹 앱**으로 기록합니다 —
**구글 계정이나 토큰을 앱에 넣지 않습니다.** 스프레드시트 편집 권한만 있으면 됩니다.

1. 위 스프레드시트를 열고 **[확장 프로그램] → [Apps Script]**
2. 기본 코드를 지우고 프로젝트의 **`google-apps-script.gs`** 내용을 붙여넣고 저장
3. **[배포] → [새 배포] → 유형 [웹 앱]**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** ← 반드시
4. **[배포]** → 권한 승인 → **웹 앱 URL 복사** (`.../exec` 로 끝남)
5. 앱 `⚙️ 설정 → 구글 시트 연결` 에 URL 붙여넣고 **[저장] → [연결 테스트]**

설정 화면의 **[📖 설치 방법]** 버튼에도 같은 안내가 있습니다.

### 기록 규칙
- **월마다 새 시트**를 만든다 (시트 이름 = `YYYY-MM`, 예: `2026-08`)
- **1행은 공백**
- **2행에 전체 항목명** (열 순서 = `🧩 항목 설정` 순서, 앞에 `작성일시`·`작성자` 2열)
- **3행부터** 리포트가 한 줄씩 쌓인다
- 항목 설정을 바꾸면 2행 헤더가 자동으로 갱신된다
- **사진은 링크가 아니라 이미지 자체가 해당 칸에 삽입된다.** 여러 장이면 가로로 나란히 배치되고
  행 높이가 자동으로 늘어난다. (앱이 사진 바이트를 보내고 스크립트가 `insertImage` 로 넣는다)
- 태블릿 사진은 업로드 전에 **최대 1600px / JPEG 로 자동 축소**된다 (4MB → 약 300KB).
  원본은 서버 `data/media/` 에 그대로 보관된다.
- 영상·PDF 는 시트에 넣을 수 없어 링크로 기록된다. 이때만 `서비스 주소`가 쓰인다.

동시에 여러 명이 올려도 줄이 섞이지 않도록 스크립트에 잠금(LockService)이 걸려 있습니다.

### 차량 재고도 구글 시트로 관리된다

구글 시트가 연결되어 있으면(웹 앱 URL 설정) 스프레드시트의 **차량재고** 탭이
차량 재고의 팀 공유 원본이 됩니다. 별도 설정은 없습니다.

- 표 모양: 2행 헤더 = `부품명 | 최소보유 | <차량 이름들…>`, 3행부터 부품 한 줄씩.
  **품목 목록은 모든 차량 공용**이고 수량만 차량별입니다 — 앱에서 품목을 추가하면
  모든 차량에 등록됩니다(다른 차량은 0). 빈 칸은 0 으로 처리됩니다.
  품목 삭제·이름변경·최소보유 변경도 모든 차량에 함께 적용됩니다.
- 수량 `[-]/[+]` 는 시트의 해당 칸에 **즉시 기록**됩니다 — 사무실 서버 없이 LTE 에서도 됩니다.
- **시트에서 직접 고쳐도 됩니다.** 차량 이름(열 제목)·품목·수량·최소보유를 고치면
  각 기기가 재고 화면을 열 때 반영됩니다. (`🔄 시트에서 받기` 로 즉시 수신)
- 탭이 아직 없으면 재고 화면을 처음 열 때 기기 재고로 자동 생성됩니다.
- 시트 연결 중에는 [⬆️ 업데이트]가 차량·재고·수량을 덮지 않습니다 (가이드·항목 설정만 서버 동기화).
- 최소보유는 부품당 한 칸이라 **모든 차량에 같은 값**이 적용됩니다.
- 스크립트를 재배포해야 동작합니다(아래 참고).

### 가이드 3종도 시트에서 볼 수 있다 (열람용)

시트가 연결돼 있으면 가이드를 저장/삭제할 때마다 **오류 코드 가이드 · 하드웨어 교체 SOP ·
SW·명령어** 탭이 자동으로 갱신됩니다. 열 구성은 `코드/제목 | 요약 | 필요 공구 | 명령어 |
단계 | 수정일` 이며 명령어·단계는 한 칸에 줄바꿈으로 나열됩니다.

> ⚠️ 가이드 탭은 **열람용(앱 → 시트 단방향)** 입니다. 시트에서 직접 고쳐도 앱에는
> 반영되지 않고 다음 갱신 때 덮어써집니다. 가이드 편집은 앱에서 하세요.
> (차량재고 탭만 양방향입니다)

### 리포트 이력을 시트에서 읽어 온다 (v3.1)

`🗂 이력` 화면은 이제 **구글 시트의 월별 탭을 그대로 읽어** 보여 줍니다.
내 기기에서 쓴 것만이 아니라 **팀이 올린 기록 전부**가 보입니다.

- 화면 위 **네 칸이 상태별 건수**입니다. 누르면 그 상태만 걸러집니다.
- **검색**은 식당명과 날짜를 한 칸에서 함께 찾습니다 (`미트로`, `08-22`).
- **월**은 드롭다운으로 바꿉니다. 시트의 월별 탭과 그대로 이어집니다.
- 줄 오른쪽에서 **상태를 바꾸면 시트의 `상태` 열에 즉시 기록**됩니다.
  오프라인이면 쌓아 두었다가 연결될 때 자동으로 올립니다.
- 연결이 안 되면 마지막으로 받아 둔 내용을 보여 주고 화면에 그 사실을 알립니다.

#### `상태` 열과 `처리 결과` 는 다른 것입니다

| | 뜻 | 언제 바뀌나 |
|---|---|---|
| **처리 결과** (작성 화면 항목) | 그날 현장에서 확정된 사실 | 안 바뀜 — 기록으로 남음 |
| **상태** (시트 맨 뒤 열) | 지금 이 건이 어디까지 왔는가 | 이력 화면에서 계속 바뀜 |

그래서 열을 따로 둡니다. 하나로 합치면 나중에 상태를 바꿀 때
"그때 현장에서는 뭐라고 했었나"가 덮여 사라집니다.
**첫 상태만** 처리 결과에서 가져옵니다 — 완료→`조치 완료`, 재방문 필요→`조치 진행 중`,
부품 대기→`교체 예정`, 모니터링→`모니터링`. 그 외에는 `조치 진행 중` 으로 시작합니다.

시트에서 `상태` 칸을 직접 고쳐도 됩니다. 앱이 다음에 읽어 갈 때 그대로 반영됩니다.

### 사진·영상은 구글 드라이브에 저장된다 (v3.1)

첨부는 **팀 공유 드라이브**의 `필드팀 유지보수(이미지,동영상)` 폴더에 저장되고,
시트 칸에는 **링크만** 들어갑니다.

저장 구조는 이렇습니다.

```
필드팀 유지보수(이미지,동영상)/
  사진/   옥동식 서초점/ 2026-09-02/ 현장사진.jpg
  동영상/ 옥동식 서초점/ 2026-09-02/ 증상영상.mp4
```

- **사진과 영상이 각자 폴더로** 갑니다. 그 아래는 **매장 이름 → 날짜** 순입니다.
- **개인 드라이브가 아니라 팀 공유 드라이브**입니다. 개인 드라이브에 두면
  그 사람 계정 용량을 쓰고, 계정이 바뀌면 사진이 통째로 사라집니다.
- **영상도 올라가고, 이력에서 그대로 재생됩니다.** 목록에서는 ▶ 표시가 붙습니다.
- 이력 상세를 열면 **미리보기**로 보이고, 누르면 크게 봅니다.
- 공유 드라이브를 옮기면 `google-apps-script.gs` 의 `SHARED_DRIVE_ID` 만 바꾸면 됩니다.
- 공유 드라이브에 못 닿으면 업로드를 멈추지 않고 예전 위치로 저장하되,
  화면에 그 사실을 알립니다.
- 링크는 `링크가 있는 사람은 보기` 로 열립니다 (미리보기 표시에 필요).
- 크기 제한: **한 개 20MB, 리포트 하나당 25MB**. 넘으면 그 파일만 빠지고 이유가 표시됩니다.
- 사진은 올리기 전 최대 1600px / JPEG 로 줄여 보냅니다(기존과 동일).

> ⚠️ **드라이브 접근 권한 승인이 한 번 필요합니다.** Apps Script 를 재배포할 때
> 구글이 "이 앱이 드라이브에 접근하려 합니다" 라고 물어봅니다. [허용] 을 누르면 됩니다.
> 계정 소유자만 누를 수 있어 대신 처리할 수 없습니다.

> 기능 추가 후 최초 1회: 스프레드시트의 Apps Script 코드를 최신 `google-apps-script.gs` 로
> 바꾸고 **[배포] → [배포 관리] → 기존 배포 수정(새 버전)** 으로 재배포하세요. URL 은 그대로입니다.

## 4. [⬆ 업데이트] — 시트와 맞추기

상단 오른쪽 **[⬆ 업데이트]** 를 누르면 두 가지를 한 번에 합니다.

1. **올린다** — 오프라인에서 쌓인 것을 구글 시트로 보냅니다.
   작성한 리포트, 재고 수량 변경, 이력 상태 변경, 가이드 탭 갱신 전부.
2. **받는다** — 시트의 최신 내용을 다시 받아옵니다. 재고와 리포트 이력이 갱신됩니다.

현장에서 인터넷 없이 일하다가, **인터넷이 되는 곳에서 한 번만 누르면 됩니다.**
(연결이 돌아오면 자동으로도 처리되지만, 확실히 하고 싶을 때 누르는 버튼입니다)

상단바 왼쪽 칩이 지금 상태를 계속 알려 줍니다.

| 칩 표시 | 뜻 |
|---|---|
| `시트와 같은 내용 · 09-01 11:55` | 올릴 것 없음. 괄호는 마지막으로 맞춘 시각 |
| `올릴 내용 3건` (파란색) | 아직 시트에 안 올라간 것이 있음 → 버튼이 깜빡임 |
| `오프라인 · 올릴 것 3건` (주황색) | 인터넷이 없음. 연결되면 처리됨 |

> v3.1 까지 이 버튼은 "내 화면 내용을 사무실 서버의 공개본으로 만들기" 였습니다.
> 팀 공유의 중심이 구글 시트로 옮겨가면서 그 뜻이 사라져, **시트와 맞추기**로 바꿨습니다.
> 가이드·리포트 항목은 여전히 사무실 서버를 거쳐 공유되며, 이 버튼이 그것도 함께 처리합니다.

### 예외: 재고 수량은 누르지 않아도 공유된다
부품을 쓰고 `[−]` 를 누르면 인터넷이 있는 한 **바로 시트에 기록**됩니다.
재고 수량은 "실물 상태 기록"이라 즉시성이 중요하기 때문입니다.
오프라인이면 대기열에 쌓였다가 연결될 때 자동으로 올라갑니다.

## 5. 오프라인 사용

**인터넷이 없어도 앱의 거의 모든 기능이 그대로 동작합니다.** 자료가 서버가 아니라
기기 안(IndexedDB)에 있기 때문입니다.

| 하는 일 | 📴 오프라인 | 🟢 온라인 |
|---|---|---|
| 가이드 열람 · 검색 | ✅ 전부 | ✅ |
| 가이드 추가 · 수정 · 삭제 | ✅ 기기에 저장 | ✅ |
| 리포트 작성 (사진 촬영 포함) | ✅ 기기에 저장 | ✅ |
| 재고 `[−]` / `[＋]` | ✅ 기록 → 연결 시 자동 반영 | ✅ 즉시 공유 |
| 구글 시트 업로드 | ⏳ 대기열 → 연결 시 **자동 전송** | ✅ 즉시 |
| **[⬆️ 업데이트]** (팀과 주고받기) | ❌ 사무실 서버 필요 | ✅ |

- 화면 위쪽에 **📴 오프라인 — 기기에 저장하며 계속 사용할 수 있습니다** 띠가 뜨고,
  처리 대기 중인 작업 건수가 함께 표시됩니다.
- 연결이 돌아오면 **자동으로** 대기열을 처리하고 최신 내용을 받아옵니다. 누를 버튼이 없습니다.
- 시트 업로드는 기기에서 구글로 직접 보내므로 **사무실 밖 LTE 에서도** 됩니다.
  (사무실 서버가 닿지 않아도 무관)

### 처음 한 번만 필요한 것
기기에 자료가 없는 첫 실행에는 **사무실 Wi-Fi 에서 한 번** 자료를 받아야 합니다.
(`⚙️ 설정 → 📴 오프라인 사용 → [📥 서버에서 최신 자료 받기]`)
그 뒤로는 인터넷 없이 계속 쓸 수 있습니다.

### 앱 화면 자체가 열리는 원리
앱 화면 파일(HTML/CSS/JS)은 **서비스워커**가 기기에 담아 둡니다.
APK 로 설치한 경우에는 APK 안에 들어 있어 더 확실합니다.

> ⚠️ 브라우저로 쓸 때 서비스워커는 `https://` 또는 `localhost` 에서만 동작합니다.
> 사내망 `http://192.168.x.x` 로 접속하면 **자료는 기기에 남지만 앱 화면을 새로 여는 것은
> 서버가 필요합니다.** 이 제약이 없는 쪽이 APK 설치입니다.

|---|---|---|

### 6-1. APK 만들기 · 설치하기 (안드로이드)

APK 는 **GitHub 가 대신 만들어 줍니다.** 작업용 맥에 안드로이드 개발 도구를 깔 필요가 없습니다.

**① 만들기**
1. GitHub 저장소 → **Actions** 탭 → 왼쪽 **"안드로이드 APK 빌드"**
2. 오른쪽 **[Run workflow]** → 초록 버튼 클릭
3. 5~10분 기다립니다.

> ⚠️ **이 저장소는 비공개(Private)입니다.**
> APK 를 내려받는 기기의 브라우저가 **GitHub 에 로그인돼 있어야** 합니다.
> 로그인하지 않고 `.apk` 링크를 누르면 파일 대신 `Not Found` 아홉 글자만 오기 때문에
> **아무것도 없는 흰 페이지**가 뜹니다(오류 메시지도 없어 원인을 알기 어렵습니다).
> 태블릿 크롬처럼 로그인이 번거로운 기기에서는 아래 **방법 B(USB)** 를 쓰세요.

**② 태블릿에 설치** — 두 방법 중 편한 쪽으로

*방법 A. 인터넷으로* (태블릿이 GitHub 에 로그인돼 있어야 함)
1. 저장소 **Releases** 페이지를 **태블릿 크롬**으로 엽니다.
2. 맨 위 항목의 `.apk` 파일을 눌러 다운로드합니다.
3. 흰 페이지만 뜬다면 → 로그인이 안 된 것입니다. 우측 상단으로 로그인 후 다시 누르세요.

*방법 B. USB 로* — **권장** (태블릿에 인터넷도 GitHub 계정도 필요 없음)
1. **로그인된 PC** 에서 Releases 의 `.apk` 를 내려받아 **USB 에 복사**합니다.
2. USB 를 태블릿에 연결하고, 파일 앱에서 `.apk` 를 누릅니다.
3. 태블릿 여러 대라면 같은 USB 로 전부 설치하면 됩니다.

> PC 에서도 흰 페이지가 뜬다면, 그 브라우저가 저장소에 접근 권한이 있는 계정으로
> 로그인돼 있는지 확인하세요. 명령줄이 편하면 로그인 없이 이렇게 받을 수도 있습니다:
> ```bash
> gh release download build-6 --repo jiminhwang94/bh-field-portal --pattern "*.apk"
> ```

공통:
- "출처를 알 수 없는 앱" 경고 → **[설정] → 이 출처 허용** (기기당 최초 1회만)
- 설치 후 홈 화면 **현장 포털** 아이콘으로 실행합니다.
- GitHub 은 APK 를 **만들 때만** 쓰입니다. 태블릿은 GitHub 에 접속하지 않습니다.

**③ 첫 실행 (한 번만)**
1. `⚙️ 설정 → 사무실 서버 주소` 에 서버 PC 주소 입력 (예: `http://192.168.0.83:8787`)
2. `⚙️ 설정 → 📴 오프라인 사용 → [📥 서버에서 최신 자료 받기]`
3. 끝. 이제 인터넷 없이도 전부 동작합니다.

## 7. 데이터 구조

**기기 안 (IndexedDB `bh-field-portal`)** — 앱이 실제로 보고 쓰는 곳
| 저장소 | 내용 |
|---|---|
| `guides` | 가이드 + 단계 + 명령어 (한 덩어리) |
| `vehicles` / `inventory` / `quantities` | 차량 · 재고 품목 · 수량 |
| `fields` | 리포트 입력 항목 |
| `reports` | 작성한 리포트 (**이 기기에만** 있음 — 팀 공유는 구글 시트) |
| `media` | 사진 원본(blob) |
| `outbox` | 연결되면 처리할 작업 (수량 변경 · 시트 업로드) |
| `meta` | 공개본 버전 · 변경 여부 · 설정 |

**서버 (`data/app.db`)** — 팀 공개본 한 벌
| 테이블 | 내용 | 업데이트로 공유 |
|---|---|---|
| `guide_master` / `guide_step` | 가이드와 단계 (`commands` 는 JSON 문자열) | ✅ |
| `vehicle` | 차량 목록 | ✅ |
| `vehicle_inventory` | 재고 품목 정의 (`min_quantity` 이하 = 보충 필요) | ✅ |
| `inventory_quantity` | 재고 **수량** — 즉시 공유 | 즉시 |
| `report_field_config` | 리포트 입력 항목 (구글 시트 열 순서) | ✅ |
| `media` | 가이드 사진 메타 (사진 파일은 `data/media/`) | ✅ |

> 리포트는 서버에 저장되지 않습니다. 기기에 있다가 구글 시트로 갑니다.

### API 요약 (v3.0 — 서버는 동기화만 담당)
```
GET    /api/version                 GET  /api/meta
GET    /api/sync/head               ← 공개본 버전만 (가볍게 확인)
GET    /api/sync/pull               ← 공개본 전체 내려받기 (+ 팀 공통 설정)
POST   /api/sync/push               ← [⬆️ 업데이트] : 기기 내용을 공개본으로
POST   /api/sync/quantities         ← 재고 수량 즉시 반영 (마지막 기록 우선)
GET    /api/sync/legacy             ← v2 에서 서버에 남은 리포트를 기기로 이전
POST   /api/sheets/relay            ← 구글 직접 전송이 막혔을 때만 쓰는 우회 통로
GET    /api/settings                PUT  /api/settings
POST   /api/settings/sheets-test
GET    /api/auth/status             POST /api/auth
POST   /api/media?filename=...      GET  /media/{filename}
```
모든 요청에 `X-Device-Id` 헤더가 함께 전송됩니다.
APK 앱은 쿠키를 쓸 수 없어 `X-Access-Token` 헤더로 인증합니다.

> **가이드·재고·리포트 CRUD 경로는 서버에 없습니다.** 전부 기기 안에서 처리합니다.

## 9. 운영 참고

- **백업**: `tools\백업 자동실행 등록.bat` 을 한 번 더블클릭하면 **매일 저녁 7시**에
  자동으로 백업된다(윈도우 작업 스케줄러). 해제는 `tools\백업 자동실행 해제.bat`.
  수동 실행은 `python tools/backup.py`, macOS 는 `백업하기.command`.
  `backups/날짜_시각/` 에 저장되고 최근 14개를 보관한다(서버 실행 중에도 안전).
  자동 실행은 crontab 에 아래 한 줄:
  ```
  0 19 * * * cd "<프로젝트 경로>" && /usr/bin/python3 tools/backup.py >> backups/backup.log 2>&1
  ```
- **사진 정리**: `python3 tools/cleanup_media.py --dry` 로 확인 후 `--dry` 없이 실행하면
  어디에서도 참조하지 않는 사진을 삭제한다(최근 10분 이내 파일은 보존).
- **초기화**: `data/` 를 삭제하고 다시 실행하면 샘플 가이드/재고/항목이 새로 생성된다.
- **확인용 서버는 반드시 데이터 폴더를 분리한다** — `BH_DATA_DIR` 을 지정하면
  그 폴더를 쓴다. 이 값을 안 주면 **운영 데이터를 그대로 건드린다.**
  ```bash
  BH_DATA_DIR=/tmp/bh-test python server.py --port 8788
  ```
  실제로 두 번 사고가 났다(v3.0 리포트 유실, v3.2 가이드 덮어쓰기). 백업이 구했다.
  리버스 프록시 HTTPS 를 함께 쓰는 것을 권장한다.
- **테스트**: `tests/` 6종. GitHub Actions 로 push 마다 자동 실행된다.
- **업로드 제한**: 파일 1개당 40MB, 이미지/영상/음성/PDF 만 허용.
- **화면 코드 갱신**: 브라우저로 쓰는 경우 서버 코드가 바뀌면 다음 이동/복귀 시 자동으로
  새로 받는다. **APK 앱은 새 APK 를 설치**해야 화면 코드가 바뀐다(자료는 동기화로 자동).
- **백업**: 이제 서버에는 팀 공개본만 있다. **작성한 리포트는 각자 기기에 있으므로**
  서버 백업에 포함되지 않는다. 리포트의 최종 보관처는 **구글 시트**다 — 작성 후 업로드를
  미루지 않는 것이 곧 백업이다.

## 10. GitHub 원격 연결 (최초 1회)

로컬 git 저장소는 준비되어 있다(커밋 이력 포함). 원격 연결 순서:

```bash
cd "/Users/hwangjimin/Documents/비욘드허니컴/오류 코드 앱/코드"

  (github.com → Settings → Developer settings → Tokens → repo 권한).
- 이후에는 작업 후 `git add -A && git commit && git push` 만 반복하면 된다.

## 11. APK 서명 키 등록 (팀 배포 전 1회, 권장)

APK 는 **서명 키**로 서명됩니다. 키가 등록돼 있지 않으면 빌드할 때마다 임시 키가 만들어져,
**새 APK 를 기존 앱 위에 덮어 설치할 수 없습니다.** (지우고 다시 깔아야 하고, 그때
기기에 저장된 — 아직 시트에 올리지 않은 — 리포트가 사라집니다.)

한 번만 등록해 두면 이후 배포는 덮어 설치됩니다.

**① 키 만들기** (자바가 깔린 PC 에서 한 번. 없으면 `brew install openjdk` 또는
[adoptium.net](https://adoptium.net) 에서 설치)

```bash
keytool -genkeypair -v -keystore bh-release.jks -alias bh -keyalg RSA -keysize 2048 -validity 10000
```
비밀번호를 정하고, 이름/조직은 아무렇게나 입력해도 됩니다.
**이 파일과 비밀번호를 잃어버리면 덮어 설치가 영영 불가능**하니 안전한 곳에 보관하세요.

**② 파일을 글자로 바꾸기**

```bash
base64 -i bh-release.jks | pbcopy
```

**③ GitHub 에 등록**
저장소 → Settings → Secrets and variables → Actions → **New repository secret** 로 4개:

| 이름 | 값 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | ② 에서 복사한 긴 글자 |
| `ANDROID_KEYSTORE_PASSWORD` | ① 에서 정한 키스토어 비밀번호 |
| `ANDROID_KEY_ALIAS` | `bh` |
| `ANDROID_KEY_PASSWORD` | ① 에서 정한 키 비밀번호 |

이후 APK 빌드는 이 키로 서명되고, Releases 설명에 `서명 방식: release` 로 표시됩니다.
