# 다관점 코드 리뷰 (v2.0.1, 2026-08-04)

5개 관점(CEO / 개발자 / 디자이너 / 보안 / 현장 엔지니어)으로 전체 코드와 운영 구조를 리뷰했다.
각 항목은 실제 코드 확인을 근거로 하며, 심각도는 🔴 높음 / 🟡 중간 / 🟢 낮음.

**개선 항목의 실행 여부·우선순위는 [plan.md](../plan.md) 에서 결정한다.**

---

## 1. CEO 관점 — 비즈니스 가치와 리스크

### 잘된 점
- **비용 구조가 이상적**: 외부 의존성 0, 라이선스 비용 0, 서버는 기존 PC 활용.
  구글 시트·Apps Script 도 무료 티어로 충분.
- **회사 자산 축적 구조**: 엔지니어의 대응 노하우(가이드)가 개인 머릿속이 아니라
  시스템에 쌓인다. 신규 인력 온보딩 비용을 직접 줄이는 구조.
- **데이터 분석 가능**: 리포트가 월별 시트로 정형화되어 쌓임 → 방문 빈도, 오류 유형,
  소요 시간을 그대로 집계할 수 있다.
- **벤더 종속 없음**: 노션 제거 결정으로 외부 서비스 권한 문제에서 자유로워짐.

### 리스크
- 🔴 **단일 장애점(SPOF)**: 서버 PC 가 꺼지면 전 팀이 매뉴얼 열람조차 불가.
  현장 대응 도구의 다운타임은 곧 현장 서비스 지연.
  → 상시 가동 머신(사내 서버/클라우드) 이전 + 자동 재시작 등록 필요.
- 🔴 **백업 자동화 부재**: `data/` 수동 복사에 의존. 디스크 고장 = 전체 가이드 유실.
  → 일 1회 자동 백업(cron + 외부 위치) 권장.
- 🟡 **버스 팩터 1**: 구조를 아는 사람이 실질적으로 1명. 문서(README/WORKLOG)로
  완화되어 있으나, 팀 내 2번째 운영자 지정 권장.
- 🟡 **사용 현황 측정 불가**: 누가 얼마나 쓰는지 데이터가 없어 투자 판단 근거가 없음.
  (리포트 업로드 수는 시트로 간접 측정 가능)
- 🟢 도메인/브랜딩 미정: 현재 IP 접속. 정착 여부 확인 후 결정해도 늦지 않음.

**한 줄 평**: 투자 대비 효율이 매우 높은 도구. 다만 지금은 "잘 만든 시제품"의 운영 형태이므로,
정착 판단이 서는 즉시 **상시 서버 + 자동 백업**이라는 최소 운영 체계를 갖출 것.

## 2. 개발자 관점 — 구조와 코드 품질

### 잘된 점
- 계층 분리가 명확: `server(전송) → api(라우팅/검증) → db(데이터) / sheets(외부 연동)`.
- 외부 의존성 0 이 실제로 지켜짐 — 배포·업그레이드가 파일 복사로 끝난다.
- 테스트가 실사용 시나리오 기반(실서버 2기기 publish 시나리오, Apps Script 모의 서버).
- 이전 버전 DB 자동 마이그레이션(`_migrate_columns`)으로 업그레이드 안전성 확보.
- 경로 탈출 방어, 업로드 화이트리스트, 요청 크기 제한 등 기본기 있음.

### 발견 사항
- 🔴 **publish 동시성 잠금 없음** (`app/db.py`): `publish()` 가
  "공유 테이블 복사 → 리비전 읽기 → +1 저장" 을 잠금 없이 수행한다. 두 기기가 동시에
  [업데이트] 를 누르면 리비전 중복·공개본 반쪽 복사 가능.
  발생 확률은 낮지만(소수 인원) 수정 비용도 낮음 → `threading.Lock` 하나로 해결.
- 🟡 **GET 마다 파일 기반 상태 확인**: `auto_refresh_if_clean()` 이 요청마다 SQLite 연결
  2회(공개본 리비전 + 작업본 리비전). 현재 규모(수 명)에서는 무해하나, 리비전을 메모리에
  캐시하면 더 깔끔하다.
- 🟡 **고아 미디어 파일**: 리포트를 삭제해도 `data/media/` 의 사진은 남는다.
  용량이 서서히 증가 → 주기 정리 또는 삭제 시 함께 제거.
- 🟡 **JS 프런트엔드 테스트 부재**: 서버는 3개 스위트로 검증되지만 화면 로직(폼 수집,
  임시보관, 사진 축소)은 수동 검증에 의존.
- 🟢 `innerHTML` 템플릿 패턴: 현재는 `h()` 이스케이프가 일관 적용돼 있으나(확인함),
  새 코드에서 누락하면 바로 XSS 가 된다. 리뷰 체크리스트로 관리 필요.
- 🟢 사진 축소(`shrinkImage`)가 EXIF 회전을 명시 처리하지 않음. 최신 브라우저는
  `createImageBitmap` 이 회전을 반영하지만 구형 태블릿에서 눕는 사진 가능성.
  `imageOrientation: 'from-image'` 명시가 안전.
- 🟢 CI 없음: 테스트가 있어도 실행을 잊으면 무용지물. GitHub Actions 1개면 충분.

**한 줄 평**: 규모에 맞는 실용적 설계. 단 publish 잠금은 "언젠가 반드시 밟는 지뢰"라
바로 고칠 가치가 있다.

## 3. 디자이너 관점 — UI/UX

### 잘된 점
- **디자인 토큰 일관성**: 색/모서리/그림자/간격이 CSS 변수로 통일, 다크모드 자동 대응.
- **터치 우선**: 최소 44~52px 터치 타겟, 수량 조절 버튼 52px, 하단 고정 CTA.
- **"터치 2~3번 내 매뉴얼 진입" 요구 충족**: 메인 → 카테고리 → 가이드.
- 상태 피드백 존재: 토스트, 버튼 진행 중 상태, 노란 [업데이트 ●] 배지.
- 빈 상태(empty state)마다 다음 행동 안내가 있음.

### 발견 사항
- 🟡 **좁은 화면에서 앱바가 이모지만 남음**: 라벨이 숨어 🚐🗂🧩⚙️ 만 보인다.
  신규 사용자는 의미를 추측해야 함 → 하단 탭바(라벨 포함) 전환 또는 최소 2개 라벨 유지 권장.
- 🟡 **[업데이트] 개념의 학습 장벽**: "내 변경은 나만 보인다"는 모델은 설명 없이는
  직관적이지 않다. 첫 실행 1회 안내(3장 코치마크) 권장.
- 🟡 **설정 화면 과밀**: 시트 연결·기록 방식·업데이트·앱 설치가 한 화면에 세로로 나열.
  아코디언 또는 탭 분리 여지.
- 🟢 이모지 아이콘 혼용: 기기/OS 마다 렌더링이 달라 브랜드 일관성이 약함.
  단색 SVG 아이콘 세트로 교체 여지 (기능 문제는 아님).
- 🟢 접근성: 주요 버튼에 aria-label 있음, 입력 포커스 링 있음. 다만 muted 텍스트
  대비(라이트 모드 #5c6875 on #eef1f5 ≈ 4.6:1)가 작은 글자에서 경계선 수준.
- 🟢 가이드 단계의 긴 본문 가독성은 좋으나, 사진이 없는 단계가 많으면 시각적 단조로움.

**한 줄 평**: 현장 도구로서의 UI 기본기는 탄탄. 다음 과제는 "예쁘게"가 아니라
**처음 쓰는 사람이 설명 없이 이해하는가**(내비게이션 라벨, 업데이트 개념 안내).

## 4. 보안 관점 (추가 선정)

> 사내망 소수 인원 사용이라는 전제에서 평가. 도메인 공개 시 등급이 달라진다.

- 🔴 **인증 없음 + 기기 ID 클라이언트 자율**: `X-Device-Id` 를 브라우저가 만들어 보낸다.
  같은 네트워크의 누구나 접속·수정·[업데이트]·타 기기 ID 사칭이 가능.
  사내망에서는 수용 가능하나, **도메인 공개 전 반드시** 최소 공용 PIN 또는
  리버스 프록시 Basic Auth 필요.
- 🟡 **Apps Script "모든 사용자" 접근**: 웹 앱 URL 을 아는 사람은 시트에 행을 쓸 수 있다
  (읽기는 불가). URL 자체가 비밀값이므로 카톡 등에 공유하지 말 것.
  필요시 스크립트에 공유 키 검증 1줄 추가 가능.
- 🟡 **CORS `Access-Control-Allow-Origin: *` 잔존**: v1.2 허브 기능용이었고 지금은
  불필요. 제거해도 동작에 영향 없음(공격 표면 축소).
- 🟢 업로드가 Content-Type 헤더만 신뢰(매직 바이트 미검증). 화이트리스트+확장자
  정규화가 있어 실위험은 낮지만, 서버가 이미지를 재검증하면 더 좋다.
- 🟢 확인된 방어: 경로 탈출 차단(테스트 포함), `h()` XSS 이스케이프 일관 적용,
  요청 크기 제한, SQL 파라미터 바인딩 전면 사용.

## 5. 현장 엔지니어 관점 (추가 선정) — 실제 사용자

- 🔴 **온라인 전용의 현장 리스크**: 식당 지하·주방 안쪽은 신호가 약한 경우가 많다.
  장애 대응 중 매뉴얼이 안 열리는 상황이 최악의 시나리오.
  (오프라인 제거는 운영 결정이었음 — 다만 "최근 본 가이드 N개만 기기 보관" 같은
  최소 완충은 재고할 가치가 있다.)
- 🟢 **리포트 흐름이 현장 친화적**: 자동 임시보관(전화 끼어들어도 유지), 사진 자동 축소
  (약한 신호에서도 업로드 빠름), 카메라 직접 호출.
- 🟢 명령어 복사 버튼이 HTTP 환경에서도 동작 — 실기 검증됨.
- 🟡 검색이 서버 왕복 — 신호 약할 때 검색 지연 체감 가능. (규모상 클라이언트 검색 전환 용이)
- 🟢 재고 `[-]` 는 부품을 쓰는 그 순간의 동작과 일치. 다만 [업데이트] 를 잊으면
  동료 재고와 어긋남 → 노란 버튼이 완화하지만, "재고 변경은 즉시 공유" 예외 규칙도
  검토 가치 있음 (결정 필요).
