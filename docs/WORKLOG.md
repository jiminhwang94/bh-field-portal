## v1.0.0 — 최초 구축 (2026-08-01)

### 배경
- 개발 지시서 3종 수령: 기능 요구사항(현장 셀프 장애 대응 / 스타리아 재고 / 노션 전송),
  Prisma 스키마(GuideMaster·GuideStep·VehicleInventory·ReportFieldConfig), UI 화면 명세.
- **기술 스택 결정**: 지시서는 Prisma(Node) 전제였으나 개발 PC 에 Node.js/npm/Homebrew 가
  없고 Python 3.10 만 존재 → **Python 표준 라이브러리 + SQLite + 바닐라 JS** 로 결정.
  설치 없이 더블클릭 실행이 가능해 현장 배포에도 유리.

### 구현
- `server.py`: 표준 라이브러리 `http.server` 기반 HTTP 서버, 정적 파일 + REST 라우팅,
  경로 탈출(path traversal) 방어, SPA 해시 라우팅 폴백.
- `app/db.py`: Prisma 스키마를 SQLite 로 1:1 이식. `commands` 는 JSON 문자열,
  `GuideStep` 은 `ON DELETE CASCADE`. 재고에 `min_quantity`(보충 필요 표시) 추가.
- `app/api.py`: 가이드/재고/항목/리포트 CRUD + 검증. 업로드는 MIME 화이트리스트 + 40MB 제한.
- `app/notion.py`: 노션 REST API 클라이언트 (이후 v2.0 에서 제거됨).
- `web/`: 해시 라우터 SPA. 카테고리 카드 3종, 통합 검색(단계 본문까지), 가이드 CRUD 편집기,
  단계 체크리스트(localStorage), 명령어 원클릭 복사(HTTP 환경 폴백 포함),
  재고 `[-]/[+]`, 동적 리포트 폼, 자동 임시보관, 다크모드.

### 발견·수정한 버그
- 빈 단계를 건너뛸 때 `stepOrder` 가 불연속이 되는 문제 → 저장 시 연속 번호로 재부여.
- iPad(HTTP, 비보안 컨텍스트)에서 클립보드 API 불가 → `execCommand` 폴백 구현.
- 화면 이동 시 열려 있던 모달이 닫히지 않는 문제 → 라우터에서 `closeModal()` 호출.
- 모달 이벤트 리스너가 `#modalRoot` 에 누적되는 문제 → 매번 새로 생성되는 `.modal` 에 연결.

### 검증
- API 스모크 테스트 전 구간 통과, 브라우저 실기(태블릿/데스크톱/라이트/다크) 확인.

### 구현
- **차량 관리**: `vehicle` 테이블 신설(삭제한 기본 차량이 되살아나지 않도록 재고와 분리),
  차량 관리 시트(추가/삭제, 삭제 시 소속 품목 수 경고).
- **노션 스키마 임포트**: DB 속성을 읽어 리포트 입력 항목 자동 생성
  (select 선택지 → 드롭다운, title → 필수 텍스트, files → 사진, people/formula 등은 제외).
  [교체]/[추가만] 두 모드. (v2.0 에서 노션 제거로 함께 삭제)
- **PWA**: manifest + 앱 아이콘(순수 Python 으로 PNG 생성), 설치 안내, 빌드 해시 기반
  업데이트 감지 배너.

### 발견·수정한 버그 (중요)
- **SSL 인증서 오류**: python.org macOS 빌드에 루트 인증서가 없어 외부 HTTPS API 호출이
  100% `CERTIFICATE_VERIFY_FAILED`. → certifi → `/etc/ssl/cert.pem` 순으로 CA 번들을
  자동 탐색하는 `ssl_context()` 구현(검증은 유지). 이 로직은 v2.0 의 sheets.py 에도 승계.
- **토큰 칸에 URL 입력**: 사용자가 노션 페이지 링크를 토큰 칸에 저장해 401 발생
  → 형식 검증(링크/공백/접두어)과 친절한 오류 안내 추가.
- 이전 버전 DB 와의 호환을 위해 `report` 테이블 컬럼 자동 마이그레이션 추가.

## v2.0.0 — 구조 개편: 구글 시트 · 공개본/작업본 (2026-08-03 ~ 04)

### 요구 (사용자 결정 10건)
1. 노션 관련 전부 삭제 (팀 스페이스 일반 참여자라 토큰/API 접근 불가)
2. 리포트를 **구글 스프레드시트**에 업로드
3. **월마다 새 시트**, 1행 공백 / 2행 항목명 / 3행부터 데이터
4. "필드" → "항목 설정" 명칭 변경
5. 오프라인 기능 전부 삭제 (온라인 전용)
6. 생성/수정/삭제는 실시간 공유하지 않고 **[업데이트]** 를 눌러야 전체 적용
7. "내보내기" → "업데이트" 명칭, 가져오기 버튼 삭제 (자동 수신)
8. 기기 이름 1회 등록 후 계속 사용

### 구현
- **구글 시트 업로드** (`app/sheets.py` + `google-apps-script.gs`):
  Sheets API 는 OAuth/서비스 계정이 필요해 일반 팀원이 쓰기 어려움 →
  스프레드시트에 붙이는 **Apps Script 웹 앱** 방식 채택 (계정/토큰을 앱에 넣지 않음).
  월별 시트 자동 생성, LockService 로 동시 업로드 줄 섞임 방지.
- **공개본/작업본 모델** (`app/db.py` 재작성):
  - `data/app.db` = 공개본(모두가 보는 내용), `data/drafts/<기기ID>.db` = 기기별 작업본
  - 모든 요청에 `X-Device-Id` 헤더 → 그 기기의 작업본에서 읽고 씀
  - `[업데이트]` = 작업본의 공유 테이블을 공개본으로 복사 + 리비전 +1
  - 다른 사람이 업데이트하면, 내 변경이 없는 기기는 **자동으로 최신 수신**
  - 내 변경 + 남이 먼저 업데이트 → 경고 후 진행(덮어쓰기) 또는 [내 변경 버리고 최신 받기]
  - 리포트·기기 설정은 작업본 전용(개인 데이터), 시트 연결·서비스 주소는 공개본(전역)
- 미적용 변경이 있으면 [업데이트] 버튼 노란색 + ● 표시.

### 발견·수정한 버그
- **자동 수신 누락**: 최신 반영이 `/api/state` 에서만 일어나 다른 화면 조회는 옛 데이터
  → 모든 GET 요청에서 `auto_refresh_if_clean()` 수행(뒤처지지 않았으면 정수 비교만).
- 기존 v1 DB 의 `report` 테이블에 새 컬럼(`sheet_name` 등)이 없어 조회 실패
  → `_migrate_columns()` 자동 마이그레이션 + 폐기된 설정 키 정리.

### v2.0.1 — 사진·주소 수정 (2026-08-04)
- **사진이 시트에 링크로만 기록되는 문제**: 서버가 URL 문자열을 써 넣었으나

- 업로드 전 클라이언트에서 **사진 자동 축소**(최대 1600px, JPEG) — 실측 87% 감소.
- 하드코딩된 도메인(`errorcode.beyondhoneycomb.com`) 제거 → **접속한 서버 주소 자동 감지**

  반쪽 복사 방지 (리뷰에서 🔴 로 지목된 유일한 데이터 무결성 리스크)
- **B-2** CORS `Access-Control-Allow-Origin: *` 제거 (v1.2 허브 기능 잔재, 공격 표면 축소)
- **B-3** `tools/backup.py` — SQLite 백업 API 로 서버 실행 중에도 일관된 사본,
  최근 14개 보관, `백업하기.command` + cron 안내
- **B-4** `tools/cleanup_media.py` + 리포트 삭제 시 자동 정리. 참조 스캔은 공개본과

- **B-6** GitHub Actions CI — Python 3.10/3.12 에서 테스트 6종 자동 실행
- **B-7** 첫 실행 1회 안내 — [업데이트] 개념 + 재고 예외 3카드
- **B-8** 하단 탭바 (D-5)
- **B-9** 공용 PIN (D-1) — HMAC(비밀값, 기기ID+PIN) 토큰. 세션 저장소 없이 서버 재시작에도
  유지되고, PIN 을 바꾸면 모든 기존 토큰이 자동 무효화된다. `--reset-pin` 복구 경로 제공
- **B-10/B-11** 최근 가이드 20건 보관 + 목록·상세·검색 오프라인 폴백 (D-4)

- **B-13** 재고 수량 즉시 공유 (D-3)

## 남긴 교훈
1. **환경 확인 먼저**: Node 부재를 처음에 확인해 스택을 바꾼 것이 이후 모든 배포 단순화의 기반.
2. **외부 연동은 권한부터**: 노션은 기능 구현보다 "사용자가 토큰을 얻을 수 있는가"가 관건이었다.
   구글 시트도 같은 이유로 API 대신 Apps Script 를 선택.
3. **운영 방식은 사용자가 결정**: 오프라인·동기화처럼 큰 구조는 기술이 아니라
   팀의 사용 방식(온라인 전용, 명시적 업데이트)이 정한다.
4. **데이터 성격에 따라 공유 시점을 나눈다**: "문서성 데이터"(가이드·항목)는 검토 후 공개,
   "실물 상태 기록"(재고 수량)은 즉시 공유가 자연스럽다. 하나의 규칙을 강요하면 현장과 어긋난다.
5. **리뷰는 관점을 나눠야 보인다**: 같은 코드에서 CEO 는 단일 장애점을, 개발자는 잠금 누락을,
   현장은 신호 끊김을 지적했다. 한 관점으로는 절반만 본다.
