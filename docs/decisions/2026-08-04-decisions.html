D-1 접근 보호를 넣을까?

지금은 주소만 알면 누구나 열람·수정·[업데이트]가 가능합니다. 사내 Wi-Fi 전용인 동안은 낮은 위험, 도메인 공개 시 필수.

A. 지금처럼 없음

  • 설정 0, 현장에서 가장 빠른 진입
  • 같은 네트워크 손님/외부인도 접근 가능
비용: 없음 · 조건: 사내망 전용 유지

B. 공용 PIN 1개 추천

  • 첫 접속에 4~6자리 1회 입력, 기기에 기억됨 → 현장 불편 거의 없음
  • 구현 반나절, 도메인 공개 준비도 됨
  • 퇴사자 발생 시 PIN 교체 필요(전 기기 재입력)
비용: 구현 1회 · 사용 부담: 기기당 1회 입력

C. 사용자별 계정(아이디/비밀번호)

  • 누가 무엇을 했는지 정확한 기록, 개별 권한 가능
  • 구현·관리 비용이 커짐(가입/초기화/분실), 소수 인원엔 과함
비용: 큼 · 인원이 10명+ 로 늘면 재검토

D-2 서버를 어디서 돌릴까?

지금은 작업용 맥에서 실행 중 — 맥이 잠자거나 꺼지면 전 팀이 접속 불가. 리뷰에서 가장 큰 운영 리스크로 지목된 항목.

A. 현행 유지 (작업용 PC)

  • 추가 비용·작업 없음
  • PC 재부팅/이동/절전 = 서비스 중단, 사무실 밖에서 접속 불가
비용: 0 · 시험 사용 기간에만 적합

B. 사내 상시 가동 PC/서버 + 자동 시작 추천

  • 폴더 복사만으로 이전 끝(의존성 0), 자동 재시작 등록 포함
  • 자동 백업(백로그 B-3)과 함께 구성하면 운영 체계 완성
  • 여전히 사내망 안에서만 접속 (현장 밖 접속 불가)
비용: 남는 PC 1대 · 이전 작업 1시간

C. 클라우드 (고정 https 주소)

  • 현장 어디서나 접속, 도메인(errorcode.…) 연결 가능
  • 월 비용(약 5천~1만원), D-1 접근 보호가 선행 필수
비용: 월 소액 + 초기 설정 · 현장 외부 접속이 꼭 필요해지면

D-3 재고 변경도 [업데이트]를 기다릴까?

현장 관점 리뷰 지적: 부품을 쓰고 [-]를 눌러도 [업데이트] 전까지는 동료에게 안 보임 → 같은 부품을 서로 있다고 착각할 수 있음.

A. 현행 유지 — 모든 변경이 [업데이트] 일괄

  • 규칙이 하나라 단순, 실수로 누른 [-]도 업데이트 전 취소 가능
  • 업데이트를 잊으면 재고 어긋남

B. 재고 수량만 즉시 공유 추천

  • 재고는 "실물 상태 기록"이라 즉시성이 자연스러움
  • 가이드/항목 같은 "문서성 데이터"만 [업데이트] 검토를 거침
  • 규칙이 두 가지가 됨 (화면에 안내 문구로 완화)
구현: 반나절 · 품목/차량 추가·삭제는 계속 [업데이트] 대상

D-4 최소 오프라인 완충을 둘까?

온라인 전용은 확정된 방향. 다만 식당 지하 등에서 신호가 끊겼을 때 "방금까지 보던 가이드"조차 안 열리는 상황에 대한 보험 여부.

A. 없음 — 완전 온라인 전용 (현행)

  • 코드 단순, 이전에 오프라인 기능을 제거한 결정과 일관
  • 신호 끊기면 아무것도 못 봄

B. 최근 본 가이드 20개만 기기 보관 추천

  • 서비스워커 없이 localStorage 만 사용 — 이전에 문제됐던 복잡한 오프라인 구조와 무관한 가벼운 방식
  • "신호 끊김 → 방금 보던 SOP는 계속 보임" 시나리오 해결
  • 검색·재고·리포트 업로드는 여전히 온라인 필요(안내 표시)
구현: 1일 · 저장 용량: 수백 KB 수준

D-5 상단 메뉴를 하단 탭바로 바꿀까?

디자이너 관점 지적: 좁은 화면에서 상단 메뉴가 🚐🗂🧩⚙️ 이모지만 남아 처음 쓰는 사람이 의미를 추측해야 함.

A. 현행 유지 (상단 칩 메뉴)

  • 변경 없음, 기존 사용자는 이미 익숙
  • 신규 사용자 학습 장벽, 태블릿 세로 모드에서 라벨 소실

B. 하단 탭바 (아이콘+라벨 항상 표시) 추천

  • 홈/재고/리포트/항목/설정 라벨이 항상 보임 — 모바일 앱 관례와 일치
  • 엄지 닿는 위치라 태블릿 한 손 조작에 유리
  • [업데이트] 버튼 위치 재배치 필요, 화면 하단 공간 소모
구현: 1일 · [새 리포트] 버튼과의 배치는 시안으로 먼저 확인
