📱 오프라인 앱(APK) 전환 — 설명 · 미리보기 · 결정

2026-08-05 · 아래 그림은 구현 전 미리보기(목업)입니다. 끝의 회신 방법대로 답하시면 그대로 만듭니다.

1. 어떻게 "진짜 앱"이 되나

APK 는 안드로이드 설치 파일입니다. 스토어 없이도 파일을 받아 설치하면 홈 화면 아이콘 · 앱 목록 등록 · 전체화면으로 도는 진짜 앱이 됩니다.

지금 앱이 오프라인에서 안 되는 이유는 딱 하나 — 데이터가 서버(사무실 PC)에 있기 때문입니다. 그래서 이번 작업의 핵심은 APK 포장이 아니라 데이터를 통째로 기기 안으로 옮기는 것입니다. (실측: 전체 가이드+재고+항목 = 12.8KB, 사진 포함 1.3MB — 태블릿 저장소 기준 먼지 수준이라 전부 넣을 수 있습니다)

이 맥에는 안드로이드 빌드 도구가 없지만, 이미 연결된 GitHub 가 빌드 공장 역할을 합니다. 코드를 올리면 GitHub 서버가 APK 를 만들어 내려받기 링크를 제공합니다.

6. 미리 아셔야 할 제약 5가지

① APK 는 안드로이드 전용. 아이패드/아이폰은 애플이 APK 를 막아 두어 불가능합니다 — 같은 오프라인 기능을 담은 PWA(사파리 → 홈 화면에 추가)로 병행합니다.
② 스토어 앱이 아닙니다. 설치할 때 "출처를 알 수 없는 앱 허용"을 기기당 1회 눌러야 합니다. (지난번 Play 스토어 AR 오류와는 무관한, 정상적인 사내 배포 방식)
③ 앱 화면 자체의 업데이트 = 새 APK 설치. 데이터(가이드·재고)는 동기화로 자동 갱신되지만, 화면/기능이 바뀌면 새 APK 를 받아 설치해야 합니다. 앱이 "새 버전 있음"을 알려주게 만듭니다.
④ [업데이트] 동기화는 서버에 닿아야 합니다. 서버가 사무실 PC 인 지금(D-2)은 사무실 Wi-Fi 에서만 동기화됩니다. 시트 업로드는 서버와 무관해서 LTE 만 있으면 어디서나 됩니다. 사무실 밖 동기화까지 원하시면 나중에 D-2(클라우드)를 다시 열면 됩니다.
⑤ 큰 구조 변경입니다. v2.0 에서 "온라인 전용"으로 정리했던 방향을 뒤집어, 데이터 위치를 서버→기기로 옮기는 재구조화입니다. 테스트도 대부분 다시 만듭니다. 그만큼 이번 판단이 중요해서 이 문서로 먼저 확인드립니다.

7. 결정

D-6 = A. APK(안드로이드) + PWA(아이패드) 병행 추천

  • 요청하신 "다운로드해서 설치하는 앱" 그대로 (안드로이드)
  • 아이패드도 같은 오프라인 기능 사용 가능 (설치 경로만 다름)
  • 새 버전마다 APK 재설치 필요 (③)

D-6 = B. PWA 만 (APK 없이)

  • 오프라인 기능은 A 와 100% 동일, 배포가 더 단순(브라우저에서 설치)
  • "파일 받아서 설치하는 앱" 형태는 아님
회신 방법 — 그림이 의도와 맞으면 채팅으로: D-6: A, 진행해 수정하고 싶은 화면/동작이 있으면 함께 적어주세요 (예: "오프라인 배지는 더 작게"). 회신 즉시 1단계(로컬 우선 구조)부터 착수하고, 단계마다 결과를 보고합니다.
