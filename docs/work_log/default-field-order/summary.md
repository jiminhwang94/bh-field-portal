# 기본 항목 순서 — 리포트 번호가 첫 칸 (v3.26.5)

## 날짜
2026-09-16

## 요약
리포트 작성 화면의 **기본 순서**를 정했다. 리포트 번호가 언제나 맨 처음이다.

```
리포트 번호 | 매장명
로봇 시리얼 | 로봇 모델
사용 부품   | 오류 코드
현장 사진            ← 한 줄 통째로
증상 요약            ← 한 줄
조치 내용            ← 한 줄
처리 결과
```

작성 화면은 두 칸 격자라 짧은 항목은 둘씩 짝지어 놓이고, 여러 줄 항목과
첨부(MEDIA)는 `.field--wide` 로 한 줄을 다 쓴다. 위 그림이 그대로 나온다.

## 왜 리포트 번호가 먼저인가
소비자 접수 건을 먼저 고르면 **매장명이 자동으로 채워진다**(v3.26).
번호가 첫 칸이면 고르자마자 바로 옆 칸이 채워져 흐름이 끊기지 않는다.

## 변경

### web/js/local/store.js
- `DEFAULT_FIELDS` 를 위 순서로 다시 썼다.
  - **추가**: `리포트 번호`(TEXT, 필수) · `로봇 모델`(DROPDOWN,
    `Gen.1(D1),Gen.1(D2),GEN.2(M12),GEN.2(D-SUB),Frame`, 필수)
    — 팀 시트에는 있는데 앱 기본값에는 빠져 있었다.
  - **제거**: `소요 시간(분)` — 팀 시트에서 이미 빠진 항목이라, 새로 설치한
    기기가 만들었다가 첫 동기화에 지워지는 헛일을 했다.
- `applyDefaultFieldOrderOnce()` (신규) — 기본 순서를 **한 번만** 깔아 준다.
  - 순서는 기기마다 따로 두기로 했지만(v3.26.3 `reorderFields`), 그 결정
    전에 시트에서 받아 온 제각각인 순서가 이미 기기에 남아 있다.
    기준을 한 번 맞춘 뒤로는 기기에서 옮긴 순서를 건드리지 않는다.
  - 기준 표시는 meta `fieldOrderBaseline = '2026-09-16'`.
  - 기본 목록에 없는 항목(팀이 따로 만든 것)은 **서로의 순서를 지키며**
    뒤에 붙는다.
  - `listFields()` 가 아니라 `idb.getAll('fields')` 로 **원본 줄**을 읽는다
    — 화면용으로 골라 담은 쪽을 그대로 다시 쓰면 `createdAt` 을 잃는다.

### web/js/net.js
`ensureFirstData()` 에서 기본 항목을 넣은 뒤 `applyDefaultFieldOrderOnce()`
를 부른다. 자리가 갑자기 바뀌면 놀라므로 **실제로 바뀐 경우에만** 안내한다
(새로 설치해 방금 기본값을 만든 경우는 안내하지 않는다).

### 시트 [리포트 항목] 탭
같은 순서로 다시 적었다 (새로 설치하는 기기가 보는 순서).

## 테스트
- `test_design_contract.py` 에 두 줄 추가: "리포트 번호가 첫 칸이다" ·
  "기본 순서는 한 번만 깔고 그 뒤 기기 순서를 지킨다".
- 로컬 미리보기 실측:
  - 작성 화면 칸 차례가 위 그림과 일치 (긴 항목의 `[한 줄]` 여부까지).
  - 기준 표시를 지우고 다시 켜니 기본 순서로 정렬됨.
  - 두 번째 호출은 `false` (아무것도 안 함).
  - 손으로 순서를 바꾼 뒤 다시 불러도 **내 순서 그대로**.
- `test_css_contract.py` · `test_report_history.py` · `test_report_draft.py` ·
  `test_apps_script.mjs` · `test_js_parses.mjs` 통과.

## 알아둘 것
- 기존 기기는 v3.26.5 를 받고 앱을 처음 열 때 한 번 정렬된다. 그 뒤로는
  [항목 설정] 에서 옮긴 순서가 계속 남는다.
- 시트의 월별 리포트 탭 열 순서는 **이름으로** 맞추므로(v3.26 단일 표),
  이 순서 변경으로 이미 쌓인 기록이 어긋나지 않는다.
