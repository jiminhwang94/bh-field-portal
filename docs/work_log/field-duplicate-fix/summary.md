# 리포트 항목이 같은 이름으로 두 줄씩 쌓이던 문제 (v3.26.2)

## 날짜
2026-09-16

## 요약
[리포트 항목] 탭에 같은 항목이 **선택지만 다른 두 줄**로 갈라져 쌓였다
([로봇 모델] 이 `GEN.1,GEN.2(M12),GEN.2(D-SUB)` 와
`Gen.1(D1),Gen.1(D2),GEN.2(M12),GEN.2(D-SUB),Frame` 두 줄).
항목을 **ID 가 아니라 이름으로** 알아보도록 고쳐, 시트·앱 양쪽에서 같은
이름은 한 줄로 합쳐지게 했다.

## 원인 (두 겹)

**1. 기기가 항목 ID 를 새로 지어냈다** — `fieldsheet.js` `pullFields()`
```js
id: found ? found.id : store.newId(),   // ← 시트에 ID 가 있는데도 버렸다
```
시트 줄을 못 알아보면(그 기기에 아직 없는 항목이면) **시트의 ID 를 두고
새 ID 를 만들었다.** 그래서 같은 항목인데 기기마다 ID 가 달라졌다.

**2. 올릴 때 ID 로만 맞췄다** — `mergeWithSheet()`
시트 줄과 내 항목을 **ID 로만** 짝지어서, ID 가 다르면 같은 이름이어도
"시트에 없는 내 항목" 으로 보고 **뒤에 덧붙였다.** 한 기기가 [로봇 모델]
선택지를 고칠 때마다 두 줄이 됐다.

이 둘이 맞물려, 고칠수록 줄이 늘어나는 구조였다.

## 변경

### web/js/fieldsheet.js — 이름이 기준
- `labelKey(f)` — 띄어쓰기를 지운 항목 이름. 이것이 항목의 신원이다.
- `mergeWithSheet()`: 시트 줄 ↔ 내 항목을 **ID 또는 이름**으로 짝짓고,
  같은 이름·같은 ID 는 한 번만 넣는다(`add()`).
  - 방금 고친 항목 → 내 것으로 덮되 **ID 는 시트를 따른다.**
  - 안 고친 항목 → 시트 것을 그대로 둔다 (ID 가 흔들리지 않는다).
  - 내가 새로 만든 항목만 뒤에 붙는다 (시트에 같은 이름이 없을 때만).
- `pullFields()`: `id: row.id || (found ? found.id : store.newId())` —
  **시트 ID 를 따른다.** 시트에 같은 이름이 두 줄 있어도 기기엔 하나만 둔다.
  ID 가 시트 것으로 바뀌면 다시 써야 한다(`same` 비교에 `found.id` 포함) —
  안 그러면 옛 ID 짜리가 정리 단계에서 지워지며 **항목이 통째로 사라진다.**

### google-apps-script.gs — 마지막 문턱
- `dedupeFieldsByLabel(items)` (신규): 같은 이름을 하나로.
  **자리는 처음 나온 곳, 내용은 나중 것** (나중이 방금 고친 쪽 = 최신 선택지).
- `writeFieldSheet()`: 적기 전에 합친다. 어떤 기기가 중복을 올려도
  시트에는 안 쌓인다. 반환값을 실제 적은 줄 수로 바꿔 `count` 가
  보낸 수가 아니라 **적힌 수**를 알리게 했다.
- `readFieldSheet()`: 읽을 때도 합쳐서 준다 — 이미 갈라져 있는 탭이
  스스로 나아진다(기기가 중복을 받아 가면 그 기기가 다시 올릴 때
  중복이 되살아난다). 합친 뒤 순서 번호를 1부터 다시 매긴다.

## 알아둘 것
- 스크립트 배포만으로 **지금 쌓여 있는 중복은 정리된다** (읽을 때 합쳐지고,
  다음 업로드에 시트가 다시 쓰인다). 남는 [로봇 모델] 은 선택지가 더 많은
  최신 줄이다.
- 기기 쪽 재발 방지는 APK 가 필요해 **3.26.2** 로 올렸다.
- 항목 ID 가 시트 것으로 바뀌는 기기가 있을 수 있다. 리포트는 항목 **이름**
  으로 시트 열을 맞추므로(v3.26 단일 표 설계) 기록에는 영향이 없다.
