# 리포트 항목 '방문 식당명' → '매장명'

## 날짜
2026-09-16

## 요약
리포트의 식당 이름 항목을 앱·시트 모두 '매장명'으로 통일했다. 겸사겸사
2026-09 탭에 두 열로 갈라져 있던 식당 이름(옛 '매장명' / 새 '방문 식당명')을
한 열로 합치고, [리포트 항목] 탭에 3벌로 중복돼 있던 항목 설정(24줄)을
10개로 정리했다.

## 배경 / 문제
- 항목 이름이 시기에 따라 '매장명' → '방문 식당명'으로 바뀌어, 2026-09 탭에
  같은 내용의 열이 두 개 있었다 (옛 리포트 4줄은 '매장명' 열에, 새 리포트는
  '방문 식당명' 열에). 사용자가 시트에서 직접 발견.
- [리포트 항목] 탭에는 기기들이 제각각 올린 항목 목록이 3벌 쌓여 24줄이었다
  (id 만 다른 같은 항목들). 앱은 이름으로 걸러 읽어서 동작은 했지만
  순서가 마지막 등장 기준으로 뒤섞였다.

## 변경
- **시트 (운영 "필드팀 유지보수")**
  - 2026-09: 옛 '매장명' 열 값 4건(홍기와·옥동식)을 `reports:'update'` 로
    '방문 식당명' 열에 옮기고, C2 헤더를 '매장명'으로 바꿈. 비워진 옛 열(M)은
    삭제 예정 (권한 분류기가 열 삭제를 막아 오너가 직접 지우기로).
  - 2026-08: C2 헤더 '방문 식당명' → '매장명' (기록 보존용 이름 통일).
  - [리포트 항목]: `fields:'push'` 로 중복 제거 + '매장명' 개명 + 순서를
    월 탭 열 순서와 일치시켜 다시 씀 (24줄 → 10줄). 기기는 앱을 열 때
    `catchUpFromSheet → pullFields` 로 자동 반영 (이름 기준 대조라 안전).
- **앱 (web/js/local/store.js)**: `DEFAULT_FIELDS` 의 '방문 식당명' → '매장명'
  (새로 설치하는 기기용 — 기존 기기는 시트에서 받아 이름이 바뀐다).
- **tests/test_apps_script.mjs**: 검사에 쓰는 항목 이름도 '매장명'으로 통일.
- 앱의 매장 항목 인식은 원래 `label.includes('식당') || includes('매장')`
  이라 (지난 방문 찾기·드라이브 폴더명·이력 요약) 코드 수정이 필요 없었다.

## 알아둘 것
- 아직 항목 설정을 못 받은 기기(앱을 안 연 기기)가 리포트를 올리면 옛 이름
  '방문 식당명' 열이 시트에 다시 끼워질 수 있다. 그때는 값을 '매장명' 열로
  옮기고 그 열을 지우면 된다 (이번과 같은 방법).
- 임시보관(초안)에 적어 둔 식당 이름은 항목 id 가 바뀌는 기기에서 초안의
  그 칸만 비어 보일 수 있다 (다른 칸은 유지).
