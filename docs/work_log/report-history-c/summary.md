# 리포트 이력 개편 (C안 — 미조치 먼저)

## 날짜
2026-08-25

## 요약
이력 화면을 구글 시트의 월별 탭을 읽어 오는 대시보드로 바꿨다. 화면 위 네 칸이 상태별
건수이자 필터이고, 식당명·날짜 검색과 월 전환, 줄마다 상태 변경이 된다. 첨부(사진·영상)는
시트에 박아 넣지 않고 구글 드라이브에 저장한 뒤 링크만 남긴다.

## 배경 / 결정
사용자 요청 6건을 코드에 대조한 뒤 세 가지 화면안(A 시트 그대로 / B 사진으로 찾기 /
C 미조치 먼저)을 목업과 함께 제시했고 **C안**이 선택됐다.

대조 과정에서 겹치는 지점을 하나 찾아 따로 결정을 받았다. 작성 화면에 이미 `처리 결과`
드롭다운(`완료 / 재방문 필요 / 부품 대기 / 모니터링`)이 있어 새 상태 4종과 상당히 겹쳤다.
성격이 다르다고 판단해 분리를 권했고 **분리로 확정**했다.

- **처리 결과** = 그날 현장에서 확정된 사실. 나중에 바뀌지 않는다.
- **상태** = 지금 이 건이 어디까지 왔는가. 시간이 지나며 바뀐다.

합치면 상태를 바꿀 때 "그때 현장에서는 뭐라고 했었나"가 덮여 사라진다. 대신 **첫 상태만**
처리 결과에서 가져와 채운다(완료→조치 완료, 재방문 필요→조치 진행 중, 부품 대기→교체 예정,
모니터링→모니터링). 이미 있는 정보를 버리지 않으면서 열은 분리된다.

요청 5번(사진·영상을 목록에서 확인)은 지금 구조로는 불가능했다. 사진이 셀 위에 **떠 있는
그림**(`insertImage`)이라 앱이 되읽을 수 없고 영상은 아예 안 들어갔다. 드라이브 저장 +
링크 방식으로 바꿔야만 되는 요청이었다.

## 설계 결정
- **시트가 원본**: 이력은 시트에서 읽는다. 기기에는 마지막으로 받아 온 사본만 둔다.
- **줄 번호가 아니라 작성일시로 정렬**: 시트에서 사람이 줄을 옮기거나 정렬해도 화면이 흔들리지
  않는다. 상태 쓰기에는 줄 번호를 쓰되(그 칸을 정확히 짚어야 하므로) 표시 순서와 분리했다.
- **`상태` 열은 헤더 이름으로 찾는다**: 항목 설정이 바뀌어 열 개수가 달라져도 따라간다.
  없으면 맨 뒤에 만든다.
- **아직 안 올린 리포트는 위에 따로**: 시트에 없는 기기 안 리포트를 이력 목록에 섞으면
  줄 번호가 없어 상태를 못 바꾼다. 별도 구역으로 분리했다.
- **첨부 상한 20MB/25MB**: Apps Script POST 한도와 실행 시간(6분)을 고려한 값.
  넘으면 그 파일만 빠지고 이유가 화면에 표시된다.

  - 상태 타일 건수 정확(3/1/2/1 → 합 7) ✅
  - 타일 필터('진행 중' → 2건, 메타 `2 / 7건`), 해제 ✅
  - 검색: `미트로` → 4건, `08-22` → 1건, 입력 포커스 유지 ✅
  - 상태 변경 → 모의 시트 3행에 `조치 완료` 기록됨(서버 로그로 확인), 타일 즉시 재계산 ✅
  - 월 전환 2026-07 → 2건, 타일 재계산 ✅
  - 상세 모달: 제목=식당명, 처리 결과는 본문에 그대로, 상태는 칩으로 분리 표시 ✅
  - 오프라인 폴백: 안내 띠 + 마지막 사본 7건 유지 ✅
  - 오프라인 상태 변경 → 대기열 1건 → 온라인 복귀 시 자동 전송, 대기열 0 ✅
  - 라이트/다크 모드 ✅
- 테스트 7종 전부 통과 (Windows 는 `PYTHONUTF8=1` 필요)

## 발견·수정한 문제
- **정렬이 거꾸로**: 물리적 줄 순서를 뒤집는 방식이라 시트 배치에 따라 오래된 것이 위로 왔다.
  → 작성일시 기준 정렬로 변경.
- **상세 모달에 작성일시·작성자 중복**: 위 뱃지와 본문에 두 번 나왔다. → 본문에서 제외.
- **날짜 칸이 두 줄로 접힘**: `2026-08-24` 가 좁은 칸에서 줄바꿈됐다.
  → 월은 이미 위 선택기에 있으므로 줄에는 `08-24` 만 표시.
- **썸네일이 안 열리면 빈 회색 칸**: → 뒤에 `📎 열어 보기` 를 깔아 두고 이미지 실패 시 드러나게.
- **`store.js` 에 NUL(0x00) 1개**: `qtyKey` 의 구분자가 실제 NUL 이라 git 이 파일을
  바이너리로 취급해 diff 를 볼 수 없었다. → `\u0000` 이스케이프로 교체.
  `.gs` 에 이어 두 번째라 테스트로 고정했다.

## 남은 일 / 배포 절차
1. **Apps Script 재배포** — 운영("에러 코드 리포트") 활성 배포 4개를 최신 `.gs` 새 버전으로.
   이때 **드라이브 접근 권한 승인 화면이 한 번 뜬다** (계정 소유자만 누를 수 있음).
2. **서명 키 Secrets 등록** — `C:\Users\User\Documents\bh-field-portal-서명키\` 참고.
   등록 전 빌드는 임시 키라 태블릿에서 앱을 지우고 설치해야 한다.
3. **APK 빌드** — 화면 코드가 APK 안에 있으므로 새 빌드·설치 필요.
4. 첫 리포트를 올려야 그 달 탭에 `상태` 열이 생긴다. 기존 탭은 상태 칸이 비어 있고
   화면에서는 `조치 진행 중` 으로 보인다 — 시트에 직접 입력하거나 앱에서 한 번씩 바꾸면 된다.
