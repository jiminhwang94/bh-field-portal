# 리포트 월 탭 — 항목이 바뀌어도 표는 하나

## 날짜
2026-09-16

## 요약
앱에서 리포트 항목을 추가하거나 순서를 바꾸면 월별 탭에 헤더 블록(표)이
하나씩 새로 생기던 문제를 고쳤다. 이제 탭의 항목 줄은 2행 하나뿐이고,
값은 항목 **이름**으로 열을 맞춰 적는다. 이미 갈라진 탭은 다음 업로드 때
자동으로 표 하나로 합쳐진다.

## 배경 / 문제
- v3.11 설계: 항목 구성이 바뀌면 탭 맨 아래에 **새 항목 줄**을 넣고 그 아래로
  쌓았다 (옛 줄이 어긋나지 않게 하려는 의도). 그 결과 항목을 하나만 더하거나
  위치만 옮겨도 한 탭에 표가 2~3개씩 생겼다 (2026-09 탭에서 실제 발생).
- 사용자가 중복 표를 손으로 지웠더니 앱이 캐시한 행 번호가 어긋나
  시트 연동 에러까지 발생.

## 변경 (google-apps-script.gs 만 — 앱/APK 변경 없음)
- `placeForRow`: 줄 번호만 주던 것을 `{ target, map, width }` 로 확장.
  - 항목 이름으로 시트 열을 찾고, **새 항목은 직전 항목의 오른쪽에 열을
    끼워 넣는다** (`insertColumnAfter`). 순서 이동은 시트를 건드리지 않는다.
  - 없어진 항목의 열은 남긴다 (옛 기록 보존).
- 업로드: 앱이 보낸 행·첨부(media/images)의 열 번호를 map 으로 시트 열에 재배치.
- `consolidateIfSplit` (신규): 항목 묶음이 2개 이상인 탭을 업로드 시 표 하나로
  자동 통합. 열 배치는 최신 묶음 순서 + 옛 묶음의 나머지, '상태'는 맨 뒤.
  자료 줄은 각자의 항목 이름으로 재배치, 드라이브 링크는 `relinkDriveCells` 로 복원.
- 수정(update) 경로: 첨부 열 번호를 항목 이름으로 그 줄의 배치에 맞춰 변환
  (기존 잠재 버그), 수정 후 첨부 칸을 다시 파란 링크로 복원.
- `ensureColumns`: 항목이 기본 26열을 넘는 경우 대비.
- 제거: `headerKey` (블록 비교용 — 더 이상 블록을 만들지 않음).

## 알아둘 것
- **통합이 한 번 돌면 행 번호가 당겨진다.** 앱은 이력 화면을 열 때마다 행
  번호를 새로 받아오므로 자연 회복되지만, 오프라인 대기열에 옛 행 번호의
  상태 변경이 남아 있던 기기는 그 1건이 어긋날 수 있다 (기존 [삭제] 기능과
  같은 성질의 제약).
- v3.11 이전(빌드 9 이하)이 시트에 그림으로 박아 넣은 사진은 셀에 고정돼
  있지 않아, 그런 옛 달 탭이 통합되면 그림 위치가 어긋날 수 있다. 통합은
  새 업로드가 있는 탭에서만 일어나므로 지난 달 탭은 건드리지 않는다.
