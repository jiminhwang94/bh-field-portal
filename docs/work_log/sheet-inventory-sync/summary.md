# 차량 재고 구글 시트 관리 (시트 = 팀 공유 원본)

## 날짜
2026-08-25

## 요약
차량 재고(차량 목록·품목·수량·최소보유)를 사무실 서버 대신 **구글 스프레드시트의 `차량재고` 탭**으로
관리하는 옵션을 추가했다. 켜면 수량 변경이 시트에 즉시 기록되고, 시트에서 사람이 직접 고친
내용(차량 이름 변경 포함)도 앱 재고 화면을 열 때 반영된다. 사무실 서버 없이 LTE 에서도 팀이
같은 재고를 본다.

## 배경 / 동기
[⬆️ 업데이트] 공유는 사무실 서버를 거쳐야 해서, 서버가 꺼져 있거나 다른 네트워크에 있으면
기기 간 재고가 갈라졌다. 리포트가 이미 기기 → Apps Script 직접 전송으로 서버 없이 동작하므로,
같은 통로를 재고에도 적용했다. "스타리아 5868 같은 차량 이름도 시트에서 고쳐서 받게 해 달라"는
요구가 출발점.

## 변경 파일
- `google-apps-script.gs` — `inventory: pull / push / qty` 처리 추가.
  `차량재고` 탭(2행 헤더 = 부품명|최소보유|차량들, 3행부터 데이터)을 만들고 읽고 쓴다.
  기존 리포트 기록 로직은 그대로. LockService 로 동시 요청 직렬화.
- `web/js/invsheet.js` (신규) — pull/push/qty/seedOrAdopt 창구
- `web/js/sheets.js` — `callAppsScript()` 공용 호출 함수로 리팩터 (직접 전송 → 실패 시 서버 relay)
- `web/js/local/store.js` — `sheetInventory` 설정, `applyInventorySheet()`(시트 상태를 기기에 반영,
  대기 중 수량은 보존), `collectInventoryState()`, 구조 변경 시 `invsheet-push` 대기열 예약,
  `applySnapshot()` 이 시트 모드에서 차량·재고·수량을 덮지 않게 가드, compactOutbox 확장
- `web/js/sync.js` — `flushOutbox()` 분기: 시트 모드면 수량 op 를 시트로, 구조 변경 있으면 탭 전체 재작성
- `web/js/api.js` — 설정 노출(`sheet_inventory`), 차량 추가/삭제도 flushSoon
- `web/js/views/inventory.js` — 화면 열 때 시트 자동 수신, `📊 시트 연동` 배지, `🔄 시트에서 받기` 버튼
- `web/js/views/settings.js` — 토글 추가 + 처음 켤 때 seedOrAdopt (시트 비었으면 기기 내용으로 시드)
- `web/sw.js` — 오프라인 캐시 목록에 `invsheet.js` 추가 (test_offline_shell 이 잡아줌)
- `README.md`, `CHANGELOG.md` — 사용법·재배포 안내

## 설계 결정
- **시트가 원본**: 켜져 있는 동안 서버 스냅샷(pull/업데이트)이 재고를 덮지 않는다.
  가이드·리포트 항목은 기존 서버 동기화 유지 (1단계 범위 = 재고만).
- **이름이 키**: 차량 rename 은 시트에서 열 제목을 고치면 pull 때 전체 교체로 자연 반영.
  숨김 ID 행은 두지 않았다 (전체 교체 방식이라 불필요).
- **최소보유는 부품당 한 칸** — 차량별 min 이 다르면 최댓값으로 합쳐진다(문서화함).
- **수량 대기열 재사용**: 기존 outbox('quantity' op) 흐름 그대로, 전송처만 시트로 분기.
  오프라인 → 온라인 자동 처리 동작 유지. 구조 변경은 'invsheet-push' 1건으로 압축.
- **빈 칸 = 그 차량에 없는 품목**, 0 = 있는데 수량 0 (시트 편집 규약).

## 운영 적용 (A안 — 리포트 스프레드시트에 통합, 같은 날)
- 방향 결정: 재고를 별도 시트로 분리하지 않고 **기존 리포트 스프레드시트("에러 코드 리포트",
  id `1ywec2wKj0thmI0uPZeqNwCGpbD75TJ9s7Yc20iP_0z4`)에 차량재고 탭을 함께 둔다** (URL 하나 유지).
- 운영 Apps Script 갱신: 기존 코드가 리포 구버전과 동일함(커스텀 수정 없음)을 확인 후
  최신 `google-apps-script.gs` 로 교체, **버전 6** 생성.
- 활성 배포가 4개였음 → **4개 전부 버전 6으로 갱신** (URL 각각 유지 — 기기들이 어느 URL을
  쓰든 새 코드 적용). 새 배포를 만들지 않았으므로 기기 설정 변경 불필요.
- 검증: 운영 URL에 ping → "에러 코드 리포트" / 시트 [2026-08] 정상 (리포트 기능 무손상),
  `inventory: pull` → `exists:false` 정상 응답 (탭은 첫 기기가 재고 화면을 열 때 생성).
- feature 브랜치 → main 머지 완료 (로컬).

### 남은 롤아웃 순서
1. `git push` (GitHub) → 사무실 서버에서 `git pull` 후 서버 재시작 → 브라우저 기기는 자동 갱신
2. **자료가 있는 기기에서 재고 화면을 먼저 열어** 차량재고 탭을 실제 재고로 시드
   (빈 기기가 먼저 열면 빈 탭이 만들어지고, 다른 기기가 그걸 받아 재고가 비어 보일 수 있음 —
   이 경우 자료 있는 기기에서 품목을 다시 만들거나 시트에 직접 입력하면 복구됨)
3. APK 기기는 화면 코드가 APK 안에 있으므로 **새 APK 빌드·설치 필요** (GitHub Actions)
- 개발 PC의 로컬 앱은 테스트 스프레드시트("차량 재고 (현장 포털)")에 연결된 상태로 남겨둠.

## 후속 수정 2 — 품목 목록을 차량 공용으로 (같은 날)
- 문제: 5868 에서 품목(공유기 ax3008)을 추가하면 시트에는 기록되지만 4373 탭에는 안 보임.
  품목이 차량별 독립이었기 때문 (시트 빈 칸 = 그 차량엔 없음).
- 변경: **품목 = 모든 차량 공용, 수량만 차량별**로 모델 변경.
  - `store.addInventoryItem`: 모든 차량에 등록 (선택 차량은 입력 수량, 나머지 0)
  - `store.deleteInventoryItem`: 전 차량에서 삭제 (확인 문구도 갱신)
  - `store.updateInventoryItem`: 부품명·최소보유 변경을 전 차량에 적용, 이름 충돌 검사
  - `.gs` readInventory: 빈 칸 → 수량 0 으로 읽음 / writeInventory: 빈 칸 대신 0 기록
- 검증(목 서버): 4373 에서 추가 → 5868 에 즉시 0 으로 표시, 기존 품목도 pull 왕복 후
  전 차량에 나타남, 삭제 시 전 차량에서 제거, 시트에 0 명시 기록. 테스트 통과.
- ⚠️ `.gs` 가 바뀌었으므로 Apps Script 재배포 필요 (운영 4개 배포 + 테스트 시트).
- 재배포 완료: 운영("에러 코드 리포트") 활성 배포 4개 전부 **버전 7**, 테스트
  시트("필드팀 유지보수"로 개명됨) 배포 **버전 2** (URL 전부 유지).
  실제 시트 연결 상태에서 4373 탭에 공유기(ax3008) 수량 0 표시 확인 — 신고 문제 해결.
- APK 빌드 8 실행 (이 수정 포함). 빌드 7 은 이 수정 미포함이므로 태블릿에는 빌드 8 이상 설치.

## 후속 기능 — 가이드 3종 시트 열람용 탭 (같은 날)
- 요청: 차량재고처럼 오류 코드 가이드·하드웨어 교체 SOP·SW&명령어도 시트에서 보게.
- 구현: **앱 → 시트 단방향 미러** (가이드는 단계·명령어가 중첩 구조라 시트 편집 역방향은 제외).
  - `web/js/guidesheet.js` 신규: 전체 가이드를 `{guides:'push', items}` 로 전송
  - 가이드 저장/삭제 → `guidesheet-push` 대기열 → flushOutbox 에서 전송 (compact 로 1건 유지)
  - `.gs` `handleGuides`: 카테고리별 탭 3개 재작성 — 헤더
    `코드/제목|요약|필요 공구|명령어|단계|수정일`, 명령어·단계는 줄바꿈 나열, 단계에 (기준: …) 표기
- 검증: 필드팀 유지보수 시트에 탭 3개 생성·내용 확인 (오류코드 3·SOP 2·SW 2),
  대기열 경로(enqueue→flush→0건)도 실사 확인.
- 배포: 테스트 시트 스크립트 **버전 3**. 운영 스크립트도 재배포 필요(아래 절차 반복).
