## 1. 큰 그림

```
 태블릿 (APK = WebView + web/ 파일)                 구글
 ┌──────────────────────────────────┐           ┌─────────────────────────────────┐
 │ 화면 (views/*)                    │           │ Apps Script 웹 앱 (/exec)        │
 │   ↓ 읽기 · 쓰기                    │  POST     │   google-apps-script.gs         │
 │ local/store.js → IndexedDB        │ ───────→  │     ↓                           │
 │   + outbox (올릴 일 대기열)        │  JSON     │ 팀 스프레드시트 (탭들)            │
 │ sync.js — 연결되면 대기열 비우기    │ ←───────  │ 공유 드라이브 (첨부 · 백업 · APK) │
 └──────────────────────────────────┘           └─────────────────────────────────┘
```

- 앱은 **기기 우선**입니다. 모든 조회 · 저장은 IndexedDB 에서 끝나고, 시트로 보내는 일은 대기열(`outbox`)이 따로 맡습니다.
- 시트와의 통신은 전부 **Apps Script 웹 앱 하나**(`POST`, 본문은 JSON 글자)로 합니다. 앱에 구글 계정 · 토큰이 없습니다.
- 팀 웹 앱 주소는 앱에 붙박이로 들어 있습니다 (`web/js/local/store-core.js` 의 `TEAM_WEBAPP_URL`). 처음 켤 때 `connect.js` 가 설정에 적어 넣습니다.
- `server.py` 는 `web/` 정적 파일만 내주는 개발 · E2E 용 서버입니다. `/api/` 는 404, POST 등은 405.
  APK 는 화면 파일을 안에 담고 `https://appassets.androidplatform.net` 으로 열리므로 서버가 필요 없습니다.

## 2. 화면 코드 — `web/js`

빌드 단계 없이 ES 모듈 그대로 브라우저에서 돕니다.

| 파일 | 하는 일 |
|---|---|
| `app.js` | 해시 라우터 · 홈(세 개의 문) · 검색 · [패치 내용] 버튼 |
| `api.js` | 화면이 부르는 데이터 창구 — 기기 저장소를 먼저 보고, 바꾸면 곧 올리기를 예약 |
| `local/idb.js` | IndexedDB 최소 래퍼 · 저장소 정의 (`STORES`) |
| `local/store.js` | 기기 저장소 입구 — `store-core` · `-guides` · `-inventory` · `-fields` · `-driving` · `-reports` · `-work` 를 다시 내보낸다 |
| `local/store-core.js` | ID · 시각 · meta · 설정 · 대기열(outbox) · 팀 웹 앱 주소 |
| `sync.js` | 연결 상태 · 대기열을 시트로 올리기 · 올리기와 받기가 겹치지 않게 |
| `syncnow.js` | [새로고침](밀린 것 먼저 보내고 → 시트에서 받기) · 상단 칩 |
| `changes.js` | 5분마다 "시트가 바뀐 시각" 만 물어 [새로고침] 에 점 · "시트에 올렸습니다" 알림 |
| `pending.js` | [올릴 내용] 목록 · 되돌리기 · 다시 시도 |

| `sheets.js` | Apps Script 호출(`callAppsScript`) · 리포트 올리기 · 상태 값 · 첨부 한도 |

| `drivemedia.js` · `bloburls.js` | 드라이브 첨부 미리보기 · 기기 사진 blob 주소 관리 |
| `insights.js` | 매장별 이력 · 통계 · 리포트↔가이드 · '이 로봇 지난번' · 사용 부품 계산 (받아 둔 사본으로) |
| `workpicker.js` | [이슈 유형 고르기] 창 |
| `connect.js` | 팀 시트 주소 자동 등록 · 연결 확인 |
| `update.js` | [업데이트] 띠 (시트 `앱 버전` 탭) · 최소 버전 막이 (`기기` 탭 B1) |
| `errlog.js` | 화면 오류 · 올리기 실패를 모아 시트 `오류기록` 으로 |
| `mode.js` | 테스트 모드 — 연습용 시트 주소 · 따로 쓰는 DB |
| `version.js` | `APP_VERSION` — 한 곳. `tools/release.py` 가 바꾼다 |
| `patchnotes.js` | [패치 내용] 문장 (최근 12개만 둔다) |
| `ui.js` · `share.js` · `install.js` | 토스트 · 모달 · 클립보드 / 기기 공유 시트 / PWA 설치 버튼 |
| `views/` | `report` · `report-common` · `history` · `store` · `stats` · `guides` · `guide-page` · `inventory` · `driving` · `fields` · `work` · `settings` |

CSS 는 `web/css/` 의 6개 파일을 **이 차례로** 불러 뒤가 앞을 덮습니다:
`tokens.css`(색 · 간격 · 글자 — 새 색은 여기서만) → `base.css` → `touch.css` → `focus.css` → `dashboard.css` → `field.css`.

`web/sw.js` 는 서비스워커입니다. 화면 파일을 `SHELL` 목록으로 미리 담아 오프라인에서도 열리게 합니다.
**새 js · css 파일을 만들면 `SHELL` 에 넣어야** 합니다 (`tests/test_offline_shell.py` 가 잡습니다).

## 3. 기기 저장소 — IndexedDB

DB 이름 `bh-field-portal` (테스트 모드는 `bh-field-portal-test`), 버전 2. 저장소를 새로 만들면 `idb.js` 의 `DB_VERSION` 을 올려야 기존 기기에도 생깁니다.

| 저장소 | 내용 |
|---|---|
| `guides` | 가이드 + 단계 + 명령어 (한 덩어리) |
| `vehicles` · `inventory` · `quantities` | 차량 · 재고 품목 · 수량 (`차량\0품목` 키) |
| `fields` | 리포트 입력 항목 |
| `driving` | 운행일지 |
| `reports` | 이 기기에서 쓴 리포트 (임시보관 · 올리는 중 · 올림) |
| `media` | 사진 원본 blob |
| `outbox` | 시트로 보낼 일. **바꾸기 전 모습**을 함께 담아 되돌릴 수 있다 |
| `meta` | 설정 · 마지막 받기 시각 · 시트 사본(이력 · 접수 목록 등) · 최소 버전 |

## 4. 올리기 · 받기 흐름

**올리기 (자동)**

1. 화면이 `api.js` 로 바꾼다 → 기기에 저장 + `outbox` 에 한 줄 → 0.4초 뒤 `sync.runPendingWork()`.
   인터넷이 돌아올 때(`online`), 화면이 다시 보일 때, 앱을 켤 때도 돕니다.
2. `flushOutbox` 는 **한 번에 하나만** 돕니다. 받기(`sheetRead`)와 겹치지 않습니다 —
   겹치면 받기가 올리기 직전의 시트를 덮어 지운 것이 되살아났습니다.
3. 차례: 가이드 탭 → 이슈 유형 → 리포트 항목 → 운행일지 항목 → 운행일지 → 이력 상태 → 재고 → **리포트 줄**(위에서 무엇이 실패했든 반드시 시도).
   종류마다 따로 감싸 한 종류가 실패해도 나머지는 보냅니다. 끝에 모아 둔 오류를 `오류기록` 으로.
4. 실패 처리: 오프라인은 실패로 치지 않습니다. 시트가 거절한 것은 1 · 5 · 30분 뒤 다시(그 뒤 30분마다).
   다른 기기와 부딪힌 것은 `못 보냄` 으로 빼 두고 [다시 시도] 로만 다시 보냅니다.

**여러 기기가 함께 쓸 때**

- 탭을 통째로 다시 쓰는 종류(가이드 · 리포트 항목 · 재고 구성 · 운행일지 · 이슈 유형)는 **바꾼 것(changes)** 과
  받아 둔 시트의 지문(`base`)을 함께 보냅니다. 그 사이 시트가 바뀌었으면 서버가 `stale` 로 거절하고, 앱이 다시 받아 합친 뒤 올립니다.
- 재고 수량은 '바뀐 만큼' + 작업 ID 로 보내 두 번 더하지 않습니다.
- 리포트 줄은 `uploadId` 로 같은 리포트를 두 번 받아도 한 줄만 씁니다.
- 리포트 상태 · 수정 · 삭제는 줄 번호와 함께 그 줄의 작성일시 · 매장명을 보내, 줄이 밀려도 같은 리포트를 찾고 못 찾으면 멈춥니다.
- 서버는 쓰기마다 `LockService` 로 잠급니다.

**받기**

- [새로고침] (`syncnow.js`): 밀린 것을 먼저 보내고(force) → 항목 · 재고 · 가이드 · 운행일지 · 이슈 유형 · 접수 목록 · 이력을 **동시에** 받습니다.
- `changes.js`: 5분마다(화면이 보일 때만) `{changed:true}` 로 시트가 **내용상** 바뀐 시각만 묻고, 다르면 [새로고침] 에 점을 켭니다.
  서버는 이 물음에 하루 한 번 백업 · 기기 기록을 얹고, 최소 버전을 함께 돌려줍니다.

## 5. 시트 · 드라이브

### 팀 스프레드시트의 탭

| 탭 | 내용 |
|---|---|
| `YYYY-MM` | 그달 현장 리포트. 1행 비움 · 2행 항목명 · 3행부터 한 줄씩. 맨 뒤 `상태` 열. 한 달은 표 하나 — 항목이 바뀌어도 **이름으로** 열을 맞추고, 최근 달이 맨 앞 탭 |
| `오류 코드 가이드` · `하드웨어 교체 SOP` · `SW·명령어` | 가이드 3종 — 로봇 · 코드/제목 · 요약 · 필요 공구 · 명령어 · 단계 · 수정일 · 단계 사진 · 항목 · ID. 앱 ↔ 시트 양방향 |
| `가이드 로봇` · `가이드 항목` | 로봇 분류 목록 · 로봇별 가이드 항목 |
| `차량재고` | 2행 `부품명 · 최소보유 · <차량들…>`, 3행부터 품목. 시트에서 직접 고쳐도 됩니다 |
| `운행일지 …` · `운행일지 항목` | 차량별 운행일지(국세청 서식, 자료는 6행부터) · 부서/장소 선택지 |
| `리포트 항목` | 리포트 입력 항목 (팀 공통) |
| `이슈 유형 목록` | 구분 › 대분류 › 세부 항목 (v3.31 의 `작업 목록` 이 있으면 이름만 바꿔 씁니다) |
| `앱 설치 링크` · `앱 버전` | 드라이브 고정 설치 주소 · APK 버전 목록(`공개` 칸) |
| `기기` | 기기마다 앱 버전 · 마지막 연결 · 올리지 못한 것 · 마지막 오류. **B1 = 최소 버전** |
| `변경기록` · `오류기록` · `휴지통` | 쓰기마다 한 줄(5,000줄) · 기기 오류 · 지운 가이드/리포트(1,000건) |

탭 순서는 요청을 처리할 때마다 스크립트가 맞춥니다 (`arrangeTabs`). 매장이 소비자 앱으로 접수한 건은
**다른 스프레드시트**의 `[리포트]` 탭에서 읽기만 합니다 (`reports: 'numbers'` — 새 리포트의 '접수 대기').

### 공유 드라이브 (`SHARED_DRIVE_ID` 가 가리키는 폴더 아래)

```
<공유 드라이브 폴더>/
  옥동식 서초점/2026-09-02/사진/ · 동영상/     리포트 첨부 (매장 → 날짜 → 종류)
  시트 백업/                                  매일 스프레드시트 사본 (30일)
  앱 설치 파일/현장포털-설치.apk                고정 설치 링크
  업로드 조각 (자동 정리)/                      이어 올리는 중인 조각 (다 붙이면 지움)
```

공유 드라이브에 못 닿으면 스프레드시트 옆 `현장 리포트 첨부` 폴더에 대신 저장하고 그 사실을 알립니다.

### Apps Script 요청 종류 (`handleRequest`)

본문의 키 하나로 갈립니다.

| 요청 | 하는 일 |
|---|---|
| `changed` | 내용이 바뀐 시각 · 최소 버전 (+ 하루 한 번 백업 · 기기 기록) |
| `health` | 매일 점검 — 숫자만, 읽기만 |
| `ping` | 연결 테스트 (시트 이름 · 탭 목록 · 드라이브 용량) |
| `reports`: `numbers` · `months` · `pull` · `update` · `delete` · `status` | 접수 목록 · 달 목록 · 이력 읽기 · 고치기 · 지우기(휴지통) · 상태 |
| (`sheetName` + `headers` + `row`) | 리포트 한 줄 쓰기 (`uploadId` 로 중복 막음) |
| `media`: `chunk` · `finish` | 첨부 조각 올리기 · 이어 붙이기 |
| `inventory`: `pull` · `push` · `qty` | 차량재고 받기 · 구성 쓰기 · 수량 증감 |
| `guides`: `pull` · `push` · `media` | 가이드 |
| `fields` · `work`: `pull` · `push` | 리포트 항목 · 이슈 유형 목록 |
| `driving`: `pull` · `push` · `options` | 운행일지 · 부서/장소 선택지 |
| `trash`: `list` · `restore` | 휴지통 |
| `errors`: `push` | 기기 오류 모으기 |
| `drive`: `space` · `info` · `bytes` · `repair` | 드라이브 용량 · 파일 종류 · 내용 직접 받기 · 공개 다시 걸기 |
| `release`: `publish` · `latest` · `install` | CI 가 버전 적기 · 태블릿이 최신 버전 묻기 · 고정 설치 파일 갈아 끼우기 |

`doGet` 은 살아 있다는 한 줄만 돌려줍니다. 사람이 시트를 직접 고치면 `onEdit` 가 '내용이 바뀐 시각' 을 적습니다.
**새 구글 권한(OAuth 범위)을 쓰는 코드는 피합니다** — 배포한 계정이 다시 승인할 때까지 태블릿 전체가 시트에 못 닿습니다 ([운영 7장](운영.md#7-태블릿이-시트에-못-닿을-때)).

| 단위 · 계약 (Python) | `tests/test_*.py` — 화면 ↔ 스타일 · 서비스워커 목록 · 이력 · 업데이트 흐름 · 정적 서버 등이 서로 약속을 지키는지 | `python tools/run_tests.py` |
| 단위 (Node) | `test_sync_flow.mjs`(실제 앱 코드로 올리기 · 받기) · `test_js_parses.mjs`(브라우저가 읽는지) | 〃 |
| 서버 코드 | `test_apps_script.mjs` — **진짜 `.gs` 를 `tests/fake_gas.mjs` 위에서** 돌린다 | 〃 |
| 타입 · 코드 검사 | `test_typecheck.mjs` — `tsc -p jsconfig.json`. 쓰지 않는 변수 · import, 닿지 않는 코드, switch 빠진 break 도 잡는다 (ESLint 대신). `npm ci` 를 안 했으면 건너뛴다 | 〃 · `npm run typecheck` |
| 화면 (E2E) | `tests/e2e/*.spec.js` — Playwright 가 `server.py` 와 가짜 시트를 띄우고 테스트 모드로 누른다. 팀 시트 주소는 막아 둔다. 태블릿 1180px + 폰 375px(smoke) | `npm run e2e` · `run_tests.py --e2e` |

`tools/run_tests.py` 는 `tests/` 의 `test_*` 를 전부 찾아 돌리므로 새 검사는 파일만 만들면 됩니다.

### CI (`.github/workflows/test.yml`, push · PR 마다)

| 일 | 내용 |

| `test (3.10)` · `test (3.12)` | 문법 검사 → `npm ci` → `python tools/run_tests.py` |

## 8. 버전 · 배포 흐름

1. 브랜치에서 작업 → PR → CI 초록 → main 에 합친다. PR 양식의 체크 칸을 채운다.
2. 버전을 올릴 때: `python tools/release.py X.Y.Z`
   - `web/js/version.js` · `web/sw.js`(캐시 이름) · `android/app/build.gradle` 세 곳을 같이 바꾼다
   - `patchnotes.js` 에 그 버전 문장이 없으면 알려 주고, [패치 내용] 은 최근 12개만 남긴다
   - `CHANGELOG.md` 에 빈 칸을 만들고, 검사를 돌린 뒤 커밋한다
   - `python tools/release.py --check` 는 세 곳이 같은지만 본다
3. main 에 합쳐지면
   - `build.gradle` 이 바뀌었으면 → CI 가 `vX.Y.Z` 태그를 붙이고 APK 를 만든다 (사람이 태그를 올리지 않는다)
   - `google-apps-script.gs` 가 바뀌었으면 → Apps Script 자동 배포
4. 자세한 것과 되돌리기는 [운영.md](운영.md).
