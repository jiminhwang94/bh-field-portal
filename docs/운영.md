# 운영 · 장애 대응

관리자용입니다. 평소에는 할 일이 거의 없고, **일이 났을 때 차례대로 따라 하는** 문서입니다.

먼저 알아 둘 것

- **사무실 서버는 없습니다.** 태블릿은 구글(Apps Script 웹 앱)로 바로 보냅니다. 팀 자료의 원본은 구글 시트와 공유 드라이브입니다.
- **태블릿은 인터넷이 끊겨도 계속 일합니다.** 못 올린 것은 기기 대기열에 남았다가 고쳐지면 저절로 올라갑니다.
  그러니 장애 중에 **현장에 "앱을 지우라" 고 하지 마세요** — 지우면 못 올린 리포트가 사라집니다.
- 손댈 수 있는 사람이 둘입니다.
  - **구글 계정 주인** — 스프레드시트와 Apps Script 를 배포한 계정. 권한 승인 · 배포 관리는 이 계정만 됩니다.
  - **GitHub 저장소 관리자** — Actions 비밀값(Secrets) · 워크플로 실행.

---

## 1. 배포는 어떻게 일어나나

둘 다 **main 에 합칠 때 저절로** 됩니다. 손으로 태그를 붙이거나 파일을 붙여넣을 일은 없습니다.

### Apps Script (서버) — `.github/workflows/apps-script.yml`

- `google-apps-script.gs` 가 바뀐 커밋이 main 에 들어오면 돕니다. (Actions → **Apps Script 자동 배포** → [Run workflow] 로 손으로도)
- clasp 2.4.2 로 코드를 올리고 **활성 배포 전부를 같은 새 버전으로** 갱신합니다. 웹 앱 주소는 그대로라 태블릿은 할 일이 없습니다.
- 이 일만 **Node 20** 입니다 (clasp 2.4.2 가 그 버전에서 검증됨). 나머지 CI 는 전부 Node 24 (`.nvmrc`).
- 배포 설정(`appsscript.json`)은 워크플로가 매번 새로 씁니다 — 웹 앱 · 실행 사용자 "나" · 액세스 "모든 사용자" · Drive 고급 서비스.
  편집기에서 손으로 바꾼 설정은 다음 배포 때 덮어써집니다.
- 비밀값 `CLASP_CREDENTIALS` · `APPS_SCRIPT_ID` 가 없으면 **조용히 건너뜁니다** (실패로 뜨지 않음). 등록 방법은 워크플로 파일 맨 위에 있습니다.

### APK (앱) — `.github/workflows/android.yml`

1. 개발자가 `python tools/release.py X.Y.Z` 로 버전을 올린 PR 을 만든다.
2. main 에 합쳐지면 `android/app/build.gradle` 이 바뀌었으므로 **gate** 일이 돕니다.
   그 버전의 `vX.Y.Z` 태그가 없으면 `release.py --check`(세 곳 버전이 같은지) → 태그를 붙이고 → 빌드합니다. 이미 있으면 건너뜁니다.
3. 빌드: 오프라인 실행 검사 → `web/` 를 APK 안에 담기 → 서명 → `FieldPortal-vX.Y.Z-buildN.apk`.
4. 올리는 곳 세 군데
   - **GitHub Releases** — `build-N` 항목 (`.apk` 첨부, 서명 방식 표시)
   - **Dropbox** + 시트 **`앱 버전`** 탭 한 줄 → 태블릿 상단 **[업데이트] 띠**가 이걸 봅니다
   - **구글 드라이브 고정 설치 링크** — `<공유 드라이브>/앱 설치 파일/현장포털-설치.apk` 의 내용만 갈아 끼웁니다.
     주소가 안 바뀌어 카톡으로 한 번 보낸 링크가 계속 최신을 줍니다. 주소는 시트 **`앱 설치 링크`** 탭과 실행 요약에 있습니다.
   - Dropbox 비밀값이 없으면 Dropbox · 시트 기록 · 드라이브 링크를 **함께 건너뜁니다** (Releases 는 그대로).
     드라이브 링크 갱신이 실패하면 빌드는 초록인 채로 요약에 ❗ 가 뜹니다 — 그때 예전 링크는 옛 버전을 줍니다.

- 화면 · 기능이 바뀐 것은 **새 APK 를 깔아야** 현장에 갑니다. 자료(가이드 · 재고 · 항목)만 바뀐 것은 APK 가 필요 없습니다.
- PR 마다 `test.yml` 의 `apk` 일이 debug APK 가 만들어지는지만 봅니다 (서명 · 업로드 없음).

## 2. 되돌리기

### Apps Script 가 잘못 나갔을 때

**① 급할 때 — 편집기에서 이전 버전으로 (몇 분)**

1. 팀 스프레드시트 → **[확장 프로그램] → [Apps Script]**
2. 오른쪽 위 **[배포] → [배포 관리]**
3. 활성 배포(웹 앱)를 고르고 **연필(수정)** → **버전** 에서 문제 전의 버전을 고른다 → **[배포]**
   (활성 배포가 여럿이면 하나씩 전부. 자동 배포는 전부를 같은 버전으로 올립니다)
4. 웹 앱 주소는 그대로입니다. 태블릿은 다음 요청부터 옛 코드를 씁니다.

**② 제대로 — main 에서 되돌리기**

①만 하고 끝내면 **다음에 `.gs` 가 바뀌어 합쳐질 때 문제 코드가 다시 나갑니다.**
문제 커밋을 `git revert` 한 PR 을 만들어 합치세요. 합치면 자동 배포가 되돌린 코드로 새 버전을 냅니다.

되돌린 뒤 확인: 앱 **설정 → 구글 시트 → [다시 확인]**, 또는 Actions → **매일 상태 점검** → [Run workflow].

### APK 가 잘못 나갔을 때

**① 더 퍼지지 않게 막기 (먼저)**

시트 **`앱 버전`** 탭에서 문제 버전 줄의 **`공개`** 칸을 `N` 으로 바꿉니다.
태블릿 [업데이트] 띠가 그 버전을 더 이상 권하지 않습니다 (공개된 것 중 가장 높은 버전만 안내합니다).
다만 **드라이브 고정 설치 링크는 이미 문제 APK** 를 줍니다 — 고친 버전이 나올 때까지 그 링크를 새로 보내지 마세요.

**② 고친 버전을 낸다 (권장)**

문제 커밋을 main 에서 되돌리고 `python tools/release.py` 로 **버전을 하나 올려** 합칩니다.
더 높은 버전이 나오므로 [업데이트] 띠 · 드라이브 링크로 그대로 덮어 설치됩니다. 자료는 유지됩니다.

**③ 옛 버전을 강제로 막기 — `기기` 탭 B1 (최소 버전)**

시트 **`기기`** 탭 **B1** 에 버전(예: `3.48.1`)을 적으면, 그보다 낮은 앱은 화면이 **"앱 업데이트가 필요합니다"** 로 덮입니다.
못 올린 자료는 기기에 그대로 있고 업데이트 뒤 올라갑니다. 비우면 막지 않습니다.
고친 버전을 낸 뒤 문제 버전 이하를 모두 올라오게 할 때 씁니다. **B1 을 아직 없는 버전으로 적으면 모든 기기가 막힙니다.**
누가 어느 버전인지는 같은 탭의 `앱 버전` · `마지막 연결` 칸에 보입니다.

**④ 이전 APK 다시 설치 — GitHub Releases**

Releases 에서 이전 `build-N` 항목의 `.apk` 를 받을 수 있습니다. **단, 그대로는 덮어 설치되지 않습니다.**
APK 안의 번호(versionCode)가 빌드 번호라 옛 APK 는 번호가 낮고, 안드로이드는 낮은 번호를 덮어 깔지 않습니다.
지우고 깔아야 하는데, 지우면 그 기기의 못 올린 리포트 · 사진이 사라집니다. 꼭 해야 한다면

1. 시트 `기기` 탭에서 그 기기의 **`올리지 못한 것` 이 0** 인지, 기기 상단에 칩이 없는지 확인
2. B1 이 옛 버전보다 높게 적혀 있지 않은지 확인 (높으면 깔자마자 막힙니다)
3. 앱 삭제 → 옛 APK 설치 → 첫 실행에 팀 시트를 다시 받아 옵니다

> 지우지 않고 옛 코드로 돌리는 길: Actions → **안드로이드 APK 빌드** → [Run workflow] 에서 브랜치 대신 **이전 태그**(예: `v3.47.0`)를 고르면
> 옛 코드에 새 빌드 번호가 붙어 덮어 설치됩니다. 이때 드라이브 고정 링크도 그 APK 로 바뀝니다.
> 아직 실제로 해 본 적은 없는 길이니, 처음엔 태블릿 한 대로 확인하세요.

## 3. 매일 백업에서 살리기

### 백업은 이렇게 돈다

- **하루 한 번** 스프레드시트를 통째로 복사합니다. 위치는 공유 드라이브(첨부가 쌓이는 그 폴더) 바로 아래 **`시트 백업`** 폴더,
  이름은 `<스프레드시트 이름> 백업 YYYY-MM-DD` 입니다.
- **30일** 지난 사본은 드라이브 휴지통으로 갑니다 (`BACKUP_KEEP_DAYS = 30`).
- 시간 트리거가 아니라 **태블릿이 5분마다 보내는 "바뀐 것 있나" 물음에 얹혀** 돕니다. 그날 앱을 켠 태블릿이 하나도 없으면 백업도 없습니다.
  이틀 넘게 안 되면 매일 상태 점검(5장)이 이슈로 알립니다.
- 지금 바로 한 벌 뜨려면: Apps Script 편집기에서 함수 **`dailyBackup`** 을 골라 [실행] (같은 날 두 번은 안 뜹니다).

### 살리기 전에 — 더 작은 방법이 있는지

| 무엇이 | 어디서 |
|---|---|
| 가이드 · 리포트를 실수로 지웠다 | 앱 **설정 → 휴지통** (6장) — 백업까지 갈 필요 없음 |
| 누가 언제 무엇을 바꿨나 | 시트 **`변경기록`** 탭 (쓰기마다 한 줄, 최근 5,000줄) |
| 칸 몇 개를 잘못 고쳤다 | `변경기록` 의 내용을 보고 손으로 되돌리기 |

### 탭 하나를 백업에서 살리기

**스프레드시트를 통째로 바꾸지 마세요.** 스크립트는 팀 시트에 붙어 있고 웹 앱 주소가 앱에 들어 있어서,
새 파일로 바꾸면 태블릿 전체가 그쪽에 닿지 않습니다. **탭 단위로** 살립니다.

1. 공유 드라이브 → `시트 백업` → 원하는 날짜의 사본을 연다
2. 살릴 탭 이름을 우클릭 → **[복사 대상] → [기존 스프레드시트]** → 팀 스프레드시트를 고른다
3. 팀 시트에 `<탭 이름>의 사본` 이 생긴다
4. 망가진 탭은 **지우지 말고** 이름을 바꿔 둔다 (예: `차량재고 (망가짐)`)
5. 사본 탭의 이름을 **원래 이름과 똑같이** 바꾼다 — 스크립트는 탭을 이름으로 찾습니다
6. 백업 뒤에 들어온 줄은 사본에 없습니다. 망가진 탭 · `변경기록` 과 비교해 빠진 줄을 옮겨 적는다
7. 현장에 [새로고침] 을 한 번 눌러 달라고 한다. 확인이 끝나면 망가진 탭을 지운다

- 가이드 · 리포트 항목 · 이슈 유형 탭의 **맨 뒤 ID 열**(숨김일 수 있음)은 그대로 둬야 합니다. 앱이 그 칸으로 같은 줄을 알아봅니다.
- `기기` · `변경기록` · `오류기록` 탭은 살릴 필요가 없습니다 (저절로 다시 쌓입니다).

## 4. APK 서명 키

APK 는 **서명 키**로 서명됩니다. 안드로이드는 **같은 키로 서명된 APK 만** 기존 앱 위에 덮어 설치합니다.

### 어디에 있어야 하나

- **GitHub Secrets 4개** — 빌드가 여기서 꺼내 씁니다.

  | 이름 | 값 |
  |---|---|
  | `ANDROID_KEYSTORE_BASE64` | 키 파일(`.jks`)을 base64 글자로 바꾼 것 |
  | `ANDROID_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
  | `ANDROID_KEY_ALIAS` | 키 별칭 |
  | `ANDROID_KEY_PASSWORD` | 키 비밀번호 |

- **GitHub 는 백업이 아닙니다.** Secrets 는 넣을 수만 있고 다시 꺼내 볼 수 없습니다.
- 그래서 **원본 `.jks` 파일 + 비밀번호 2개 + 별칭**을 **비밀번호 관리자에 오프라인 백업**으로 둡니다 (파일 첨부 기능 사용).
  가능하면 두 사람 이상이 열 수 있게 합니다.
- **저장소 · 카톡 · 메일 · 공유 드라이브에는 두지 않습니다.** 키를 가진 사람은 이 앱인 척하는 APK 를 만들 수 있습니다.
- 키가 등록돼 있으면 Releases 설명에 `서명 방식: release`, 없으면 `debug` 와 경고가 뜹니다.
  **`debug` 로 나간 APK 는 배포하지 마세요** — 빌드마다 키가 달라 덮어 설치가 안 됩니다.

### 잃어버리면

같은 키로 서명할 수 없으니 **새 APK 가 기존 앱 위에 설치되지 않습니다.** 모든 기기에서 앱을 **지우고 새로 깔아야** 하고,
그때 **기기 안에만 있던 것 — 아직 시트에 올리지 못한 리포트 · 사진, 임시보관 — 이 사라집니다.** 시트 · 드라이브에 올라간 것은 안전합니다.

그래도 해야 한다면

1. 새 키를 만들어 Secrets 4개를 바꾼다 (아래)
2. 새 키로 APK 를 빌드한다 (버전을 올려 합치기)
3. 기기마다 **`기기` 탭 `올리지 못한 것` = 0** 이고 상단 칩이 없는지 확인한 뒤에 지우고 새로 깐다
4. 다 바꾼 뒤 `기기` 탭 B1 에 새 버전을 적어 옛 앱이 남지 않게 한다

### 키 만들기 (처음 한 번 · 잃어버렸을 때)

자바가 깔린 PC 에서:

```bash
keytool -genkeypair -v -keystore bh-release.jks -alias bh -keyalg RSA -keysize 2048 -validity 10000
base64 -i bh-release.jks            # 맥. 나온 글자를 ANDROID_KEYSTORE_BASE64 에
```

비밀번호를 정하고, 이름 · 조직은 아무렇게나 넣어도 됩니다. 만든 즉시 위처럼 비밀번호 관리자에 백업합니다.
저장소 → Settings → Secrets and variables → Actions → **New repository secret** 으로 4개를 넣습니다.

## 5. 매일 상태 점검

- `.github/workflows/health.yml` 이 **매일 오전 8시(한국)** 팀 웹 앱에 `{health:true}` 를 묻습니다. Actions → **매일 상태 점검** → [Run workflow] 로 아무 때나.
- 주소는 앱 코드(`web/js/local/store-core.js` 의 팀 웹 앱 주소)에서 읽습니다.
- **읽기만 합니다.** 시트를 바꾸지 않고 기기 기록 · 탭 순서도 건드리지 않습니다. 돌려받는 것은 **숫자뿐**입니다
  (지난 24시간 기기 오류 수 · 못 올린 것이 남은 기기 수 · 마지막 백업 날짜 · 최소 버전). 이름 · 내용은 시트에서 보세요.
- `tools/health_report.mjs` 가 문제를 찾으면 **`상태점검` 라벨의 GitHub 이슈**를 엽니다.
  이미 열린 점검 이슈가 있으면 새로 만들지 않고 **댓글**을 답니다. 문제가 없으면 아무것도 안 합니다.

### 이슈가 열리면

| 이슈에 적힌 것 | 할 일 |
|---|---|
| **서버가 답하지 않거나 오류를 냈습니다** | 7장 "태블릿이 시트에 못 닿을 때" 를 차례대로 |
| **지난 24시간 기기 오류 N건** | 시트 `오류기록` 탭 (시각 · 기기 · 앱 버전 · 화면 · 내용). 여러 기기에서 같은 오류면 버그 — 고칠 일로 넘긴다. 한 기기만이면 그 사람에게 확인 |
| **올리지 못한 것이 남은 기기 N대** | 시트 `기기` 탭의 `올리지 못한 것` · `마지막 오류` · `마지막 연결`. 그 사람에게 인터넷 되는 곳에서 앱을 켜고 칩을 눌러 이유를 보라고 한다. **앱을 지우지 말라고** 꼭 말한다 |
| **매일 백업이 N일째 안 됐습니다** | 그날 앱을 켠 태블릿이 있었는지 확인 (백업은 태블릿이 켜져야 돕니다). 켰는데도 안 되면 편집기에서 `dailyBackup` 을 실행해 오류를 보고, 공유 드라이브 접근 권한을 확인 |

다 보고 처리했으면 **이슈를 닫습니다.** 닫혀 있어야 다음 문제가 새 이슈로 열립니다.
더 안 쓰는 기기의 줄이 `기기` 탭에 못 올린 것을 단 채 남아 있으면 그 줄을 지워도 됩니다 (그 기기가 다시 켜지면 줄이 새로 생깁니다).

## 6. 휴지통 — 지운 가이드 · 리포트 되살리기

- 앱에서 가이드나 리포트를 지우면 시트 **`휴지통`** 탭에 **통째로** 들어갑니다 (최근 1,000건까지).
  리포트에 붙은 사진 · 영상은 드라이브 휴지통으로 옮겨집니다.
- 되살리기: 앱 **설정 → 휴지통** 을 펼치면(인터넷 필요) 최근 것부터 목록이 나옵니다 → **[되살리기]**.
  원래 자리로 돌아가고, 리포트의 사진 · 영상도 드라이브 휴지통에서 꺼내 링크가 다시 살아납니다.
- 되살리면 `휴지통` 탭의 `되살림` 칸에 시각 · 누가 가 적히고, 같은 줄은 두 번 되살릴 수 없습니다. `변경기록` 에도 남습니다.
- `휴지통` 탭의 **`자료(고치지 마세요)`** 칸은 손대지 마세요. 되살릴 때 그 내용을 그대로 씁니다.
- 드라이브 휴지통은 시간이 지나면 비워지므로, 오래된 리포트는 글은 돌아와도 사진이 안 돌아올 수 있습니다.
- 휴지통에 들어가지 않는 것 — 재고 품목 · 운행일지 · 리포트 항목. 이것은 `변경기록` 을 보고 손으로 되돌리거나 3장의 백업에서 살립니다.

## 6-1. 시트의 날짜 순서 (v3.49.2)

- 운행일지 탭은 쓸 때마다 사용일자순(오래된 것이 위)으로 다시 적힙니다. 리포트는 작성일시 자리에 들어갑니다.
- 예전에 뒤섞인 탭은 시트 위 메뉴 **[현장 포털 → 날짜순으로 정리]** 를 한 번 누릅니다. 처음 누를 때 구글이 권한 승인을 물을 수 있습니다 (스크립트 주인 계정으로).
- 건너뛴 탭은 화면 오른쪽 아래 알림에 이유가 나옵니다 (날짜 없는 줄 · 칸에 박힌 사진 등). 그런 탭은 시트에서 손으로 정렬합니다.

## 7. 태블릿이 시트에 못 닿을 때

**모습**: 설정 → 구글 시트가 `연결 안 됨`, 여러 기기에 `못 보냄`, 상태 점검 이슈 "서버가 답하지 않거나…".
그동안에도 현장은 기기에 저장하며 계속 일합니다. 고쳐지면 쌓인 것이 저절로 올라갑니다.

차례대로 확인합니다.

1. **한 대만 그런가?** → 그 기기의 인터넷. 앱 **설정 → 구글 시트 → [다시 확인]**.
   `주소 직접 입력` 에 엉뚱한 주소가 들어가 있으면 비우거나 팀 주소로 고칩니다 (팀 주소는 앱에 들어 있습니다).
2. **웹 앱 주소를 브라우저로 열어 본다** (`…/exec`). 정상이면
   `{"ok":true,"message":"현장 리포트 수집 스크립트가 동작 중입니다."}` 가 보입니다.
   404 · 구글 로그인 화면 · 권한 요청 화면이 뜨면 아래 3 · 4.
3. **배포 설정** — 편집기 → [배포] → [배포 관리] → 활성 배포가 **웹 앱**이고
   실행 사용자 **나**, 액세스 **모든 사용자** 인지. 웹 앱 항목이 빠져 `/exec` 가 404 가 된 적이 실제로 있습니다.
   액세스가 '모든 사용자' 가 아니면 태블릿은 로그인 화면을 받고 아무것도 못 올립니다.
4. **새 권한(OAuth 범위)이 생겼나?** — 최근 `.gs` 가 새 구글 서비스를 쓰기 시작했으면(예: 외부 주소 부르기, 새 고급 서비스)
   **배포한 계정 주인이 다시 승인할 때까지 태블릿 전체가 시트에 못 닿습니다.**
   계정 주인이 편집기에서 함수 하나(예: `dailyBackup`)를 [실행] → 권한 검토 → **[허용]**. 다른 사람이 대신할 수 없습니다.
   그래서 코드는 새 권한을 쓰지 않으려고 애씁니다 — PR 에서 새 권한이 보이면 합치기 전에 계정 주인과 시간을 맞추세요.
5. **배포가 중간에 실패했나?** — Actions → **Apps Script 자동 배포** 기록. 실패하면 서버는 옛 코드로 남습니다.
   인증 값이 이상하면 그 일이 "등록된 값의 모양 점검" 단계에서 무엇이 틀렸는지 알려 줍니다. 고친 뒤 [Re-run].
6. 그래도 모르겠으면 2장의 ① 로 **바로 전 버전으로 되돌려** 현장을 먼저 살리고 원인을 찾습니다.

고쳐진 뒤: 설정 → [다시 확인] 으로 확인하고, 매일 상태 점검을 손으로 한 번 돌려 둡니다.
